# Adversarial Kinetic Probe Design — pulse-family contract v0.1

**Status:** wire-contract prototype; no physical plasma run is authorized by the included fixture.

## Canonical intervention

The initial family uses an instantaneous sinusoidal velocity kick:

\[
v^+(x)=v^-(x)+A\sin\left(2\pi m\frac{x-x_{\min}}{L}+\phi\right).
\]

Here \(A\) is the maximum absolute velocity increment in the declared normalized velocity unit, \(m\) is an integer spatial mode over the periodic domain, and \(\phi\) is in radians. The map is the velocity-kick step generated by a spatially periodic potential impulse. It is a controlled external intervention, so particle kinetic energy need not be conserved across the kick; the pre/post energy and momentum changes must be recorded.

This is a deliberately narrow first family. It avoids ambiguities about pulse-envelope normalization and gives the reference and compressed branches exactly the same intervention map. Finite-duration pulses and richer operators require new versioned operator definitions.

## Implemented validation boundary

JSON Schema validates the wire shape and local numeric ranges. The `symthaea-plasma-probes` Rust crate adds semantic checks for ordered physical/control ranges, unit agreement, the declared time horizon, a positive post-pulse observation window, mandatory controls and response metrics, sealed-test acquisition lockout, pinned confirmation identity for confirmation/sealed roles, and synthetic-fixture physical-execution lockout.

The Rust crate also provides deterministic bounded grid enumeration and a BLAKE3 identity:
- phase is wrapped to [-pi, pi);
- signed zero is canonicalized;
- zero-amplitude candidates collapse to one no-op identity;
- the family fingerprint binds the physics cohort, control bounds, initial-state digest, reference solver revision, generator seed and source-record references;
- candidate-representation revision is intentionally excluded so the same physical pulse can be matched across representation competitors.

The schema and validator still do **not** prove that a referenced commit or data digest exists, that two references are truly independent, that an intervention is physically justified for a particular checkpoint, or that energy/momentum accounting is correct. Those require the run/evidence layer and an independent reference.

A selected intervention remains a *candidate witness*. It becomes a confirmed physical counterexample only after independent replay and spatial, velocity-domain and timestep refinement.

A finite search provides empirical intervention coverage; it is not a continuous worst-case certificate without a separate, justified covering or regularity argument.


A family also declares a strictly positive minimum post-pulse observation duration. The latest admissible pulse time plus this duration must fit inside the physical horizon; a pulse at the final time cannot count as a future-response probe.


## Matrix-free empirical response Gramian primitive

The symthaea-plasma-probes crate also exposes EmpiricalGramian. It stores weighted direction factors g_i = sqrt(w_i) d_i and represents W = sum_i g_i g_i^T without materializing a dense state-by-state matrix. It provides:
- matrix-free Wv;
- quadratic form v^T Wv;
- trace;
- response-Gramian trace captured by a caller-supplied orthonormal retained basis;
- factor / scalar-storage counts.

For reachability, factors can be propagated intervention increments. For observability, factors can be pullbacks of output-sensitivity directions to the checkpoint state. The caller must derive these from the actual discrete solver and frozen control/QoI contract.

The current implementation is a positive-semidefinite factorized Gramian primitive only. It does not compute tangent operators, solve adjoints, perform balancing / SVD, certify nonlinear response bounds, or authorize a representation transition. Five additional manufactured small-matrix tests check the factorized operator against the explicit 2x2 Gramian, validate cost / dimension / finiteness guards, and check basis trace capture. These tests are authored but require Rust compilation and execution before being treated as passing.


## Phase-resolved response spectroscopy primitives

The crate also exposes:
- `ComplexResponse`: a finite complex coefficient with explicit real/imaginary quadratures;
- `ModeResponseMatrix`: output-mode by input-mode coefficients, preserving declared mode order and leaving unmeasured entries as `None`;
- relative complex Frobenius error only when the mode axes match and both matrices are complete;
- signed first-order and diagonal second-order finite-amplitude coefficients;
- mixed second-order coefficients from the four signed combinations;
- wrapped phase difference, returning no value if either response has zero magnitude.

The diagonal second-order estimator returns the Taylor coefficient multiplying A^2, not the unscaled second derivative. The mixed estimator identifies one registered mixed control direction, not a general Volterra kernel. Neither may be interpreted as an asymptotic derivative until amplitude convergence has been established on independent physical runs.

The response matrix is an analysis primitive, not a Vlasov pulse executor. It does not create the physical input-output data, establish reference convergence, or authorize branch association. It intentionally distinguishes a missing coefficient from a measured zero.


## Intervention-conditioned storage accounting

The crate exposes StateStorageBreakdown and KineticStorageAccounting for the KIRD programme (#13420). The ledger sums actual serialized checkpoint payload bytes together with basis/codec, coordinate/normalization, component/lineage, residual-memory, uncertainty/validity and provenance/contract metadata.

Persistent model and decoder assets are accounted separately and can be amortized across a declared rollout count. Peak working-set memory is recorded separately, not added to persistent checkpoint storage. Overflow and zero-rollout amortization fail closed.

This is byte accounting, not a rate–distortion evaluator. It does not calculate physical response distortion or a qualified R(D) curve; those depend on the independently referenced response/fidelity measurements and gates.


## Sample-support normalization primitive

The crate exposes MinMaxCoordinateMap as a testable affine min–max transform. Its fitted input support and caller-selected output interval are explicit; empty samples, degenerate support, non-finite coordinates and invalid output intervals fail closed. Values outside the fitted interval extrapolate and are not silently clipped.

A synthetic Rust regression test adds a point at x=0 to the inlier set [0.1, 0.3, 0.5, 0.7, 0.9] and measures the resulting displacement of every existing inlier under an explicitly supplied illustrative [-pi, pi] interval. The generic Rust primitive is not itself a NEOPIC implementation. The separate source-pinned fixture [PR #13417](https://github.com/Luminous-Dynamics/symthaea/pull/13417) uses the exact tagged NEOPIC arXiv v1 affine map to [0,1], and splits the native equal-weight sample perturbation from the weighted-measure extension. Neither test measures learned field error. See [#13416](https://github.com/Luminous-Dynamics/symthaea/issues/13416).


## Topology-aware particle lifting primitives

The crate also exposes two separate feature maps for the TAPL programme (#13447):

- `PeriodicTorusLift` emits interleaved cosine/sine Fourier-character features for harmonics 1 through a bounded maximum. It wraps the coordinate modulo one and does not append the raw coordinate, so features and their derivatives agree at the periodic seam.
- `OpenBoundaryCoordinateLift` retains the normalized coordinate plus distances to the lower and upper physical faces. It does not wrap and rejects coordinates outside [0,1].

Manufactured tests check exact seam equivalence at xi=0 and xi=1, near-seam continuity, derivative continuity, integer-period translations, and the distinction between the two open-boundary faces. These are analytic feature-map tests only: they do not train or evaluate a particle-field operator, prove field equivariance, or validate a physical plasma trajectory. Boundary type must come from the physical cohort contract, never from the current particle cloud.
