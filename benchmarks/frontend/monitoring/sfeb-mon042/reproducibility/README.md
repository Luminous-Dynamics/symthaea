# MON-042 — Dependence-Aware Reproducibility Evaluator v0.1

MON-042 prevents repeated observations that share declared failure domains from being counted as independent Bernoulli trials.

## Estimand

The evaluator forms dependency clusters by connecting execution units that share an identifier in any preregistered critical failure-domain class. It treats each connected component as one cluster. A cluster succeeds only when every replay in every member unit is complete and produces the exact target blocked verdict and exact target failure-signature digest.

The reported one-sided Clopper–Pearson bound is therefore on the probability that an independently sampled dependency cluster completes the entire preregistered replay schedule successfully. It is **not** a per-replay failure probability and is not a direct replacement for MON-040's per-replay estimand.

Missing or incomplete runs make their cluster a non-success; they never reduce the denominator. Overlapping units are clustered, not counted separately. A mixed-stratum input is rejected; analyze distinct strata separately. V1 also requires equal execution-unit counts per dependency cluster before applying a pooled binomial interval; unequal cluster sizes are held for separate stratified analysis because all-runs-success probabilities can differ by cluster size.

## Required domain classes

The experiment preregisters its required critical-domain classes. Include every relevant shared failure source (for example executor/host, hypervisor, storage failure domain, network failure domain, clock/time source, identity authority, orchestrator, control plane, credential authority, region/zone and external service). The input binds a preregistered sampling-frame digest and selection-protocol digest. Every unit has a unique selection ordinal and a digest-bound selection receipt. Each unit supplies one stable ID per required domain class plus a digest over its unit ID and domain map. Every replay also binds the same trial, scenario, recovery boundary, fault-set digest and exact code revision. Its seed must belong to the fixed preregistered seed schedule, which is identical across units; replay IDs are globally unique. Domain inventory completeness and stable identifiers must be established by independent infrastructure evidence, not generated by the replayed system.

A domain class omitted from the required list cannot be considered by this evaluator. The benchmark protocol must review the list before the study begins.

## Output interpretation

- design_verdict evaluates structural completeness, domain overlap and preregistered sample geometry, independently of whether the statistical threshold is met.
- statistical_verdict applies the exact one-sided Clopper–Pearson lower bound across dependency clusters only when the declared cluster count and unit frame match the preregistration.
- campaign_verdict is always indeterminate; input domain maps and receipt digests are not authenticated by this prototype.
- production_use_permitted is always false.

The domain graph detects declared overlap. It does not prove that undeclared common-cause dependencies are absent. The unit inventory, trust roots, source identities and outcome receipts must be authenticated through MON-041 before any runtime inference. Even then, independence and representativeness remain experiment-design assumptions requiring independent review.

## CLI

Run: go run ./cmd/qualify --input INPUT.json

Exit codes: 0 statistical threshold met under declared cluster design (campaign still indeterminate); 2 blocked; 3 indeterminate; 64 usage; 65 malformed input; 66 input unavailable; 74 output failure.

Run bash CHECKS.sh for formatting, vet, unit, race, strict CLI, schema and benchmark checks.
