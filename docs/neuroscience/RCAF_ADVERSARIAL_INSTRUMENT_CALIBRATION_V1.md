# RCAF Adversarial Instrument Calibration Protocol V1

**Status:** Partially implemented and focused-workflow validated; broader nuisance families, end-to-end empirical data and external confirmation remain outstanding.  
**Date:** 2026-11-21  
**Parent:** CETB V1 / RCAF benchmark constitution  
**Purpose:** Qualify a measurement pipeline against known latent truth, nuisance-only changes, deliberate leakage and independent transport conditions.

## 1. The next scientific question

The current RCAF simulation establishes that its Rust comparison kernel and three matrix-similarity definitions respond to changes generated by a Gaussian factor model with stationary AR(1) dependence. It does not yet establish calibration under realistic measurement degradation, nuisance shifts, nonstationarity, heterogeneous responses or analysis-selection failures. The executable challenge now includes direction-aware signal recovery, a shared observation-only nuisance sweep, and a crossed signal-plus-nuisance cell. These remain synthetic implementation calibrations, not biological validation.

The next increment is not simply a larger number of Monte-Carlo draws. It is an **adversarial instrument challenge**: hold the latent target fixed while changing the observation process, then hold the observation process controlled while changing the target. A qualified method must distinguish these cases.

Two injection levels must remain separate:

1. **Representation-level injection:** perturb already-estimated matrices. This isolates the RCAF comparison statistic and its inference from upstream estimation.
2. **Signal-level injection:** perturb synthetic parcel/sensor time series or source activity before connectivity estimation and preprocessing. This qualifies the end-to-end estimator-plus-comparator pipeline. Ground-truth networks and injection metadata must remain inaccessible to the analysis stage.

A matrix-level pass must never be presented as end-to-end signal recovery.

## 2. Separate the two estimator layers

The current three-way tournament primarily compares **matrix-comparison functions** on matched matrices. It does not yet benchmark all methods that construct a connectivity matrix from time series. CETB must make this distinction explicit.

| Layer | Input → output | Candidate families |
|---|---|---|
| Connectivity construction | Parcel/sensor time series → connectivity matrix | Pearson, Spearman, shrinkage covariance, OAS/Ledoit–Wolf precision, partial correlation, selected pyspi statistics |
| Matrix comparison | Two connectivity matrices → similarity/distance | Absolute WJ, signed-shift WJ, normalized edge error, matrix rank correlation, Frobenius/spectral distance, graph-topology distances |

Do not compare across layers as if all candidates estimate the same object. Freeze the target construct, representation, edge support and sign semantics before comparing methods. Candidate families beyond the three current RCAF comparators are research targets, not implemented functionality.

## 3. Adversarial scenario families

### 3.1 Latent-truth scenarios

- **Exact null:** same participant-level latent network in both conditions; only finite-sample estimation noise differs.
- **Localized effect:** a predeclared module or edge subset changes.
- **Distributed weak effect:** many edges change by a small amount.
- **Polarity effect:** selected edges change sign while magnitude is controlled.
- **Transient effect:** the change exists only in a predeclared temporal interval or state.
- **Partial response:** only a declared proportion of participants respond.
- **Mixed-direction response:** participant effects include both positive and negative directions.
- **Heterogeneous response:** response magnitude varies by participant and site.

### 3.2 Nuisance-only nulls

The latent network is held fixed. The observation process changes between sessions or sites. These are the critical false-positive controls:

- scanner/site gain, offset or scale changes;
- shared global/common-mode nuisance factors;
- motion-like bursts, censoring and unequal retained duration;
- parcel/edge dropout and MCAR, MAR or MNAR missingness;
- changing SNR and measurement noise;
- stationary autocorrelation sweeps and nonstationary drift;
- acquisition/session differences and preprocessing perturbations;
- modality-specific source leakage, sensor mixing or hemodynamic-response variation when the signal generator supports them.

The key invariant is that nuisance-only changes do not alter the declared latent target. If the analysis calls them neural network changes, the instrument has failed that challenge even when it detects planted biological effects elsewhere.

### 3.3 Crossed signal × nuisance interaction

The implementation now evaluates a matched signal-plus-nuisance observation in addition to the signal-only and nuisance-only cells. For each participant/replicate, the nuisance-only and combined observations share the same deterministic innovations; only the planted module loading differs. At zero nuisance dose, the combined observation reuses the exact clean injected observation. Across positive nuisance doses, clean null and clean signal metrics are held matched, while combined-cell directional recovery, wrong-direction rejection and paired-gap magnitude are allowed to change.

This is the crucial interaction test: a method can pass the clean injection and nuisance-only challenges but still fail when an artifact masks, exaggerates or reverses a genuine signal. The current crossed experiment remains limited to the same Gaussian factor model and one shared AR(1) common-mode factor. It does not yet model motion, scanner/site gain, structured spatial artifacts, censoring, physiological waveforms or empirical acquisition.
### 3.4 Deliberate leakage challenges

Each leakage pathway must have a planted-positive control and a clean negative control. At minimum test:

- participant identity overlap across train/test;
- site/scanner overlap or site confounding across folds;
- preprocessing, normalization, imputation or harmonization fit before splitting;
- feature, edge, atlas or estimator selection using held-out outcomes;
- threshold, calibration or checkpoint selection using the test cohort;
- target construction from variables that are also supplied as predictors;
- decision-level fusion fit on participants later scored by that fusion model.

The acceptance criterion is not merely that accuracy falls after correction. The audit must identify the planted pathway, show which data crossed the boundary, and demonstrate that the clean negative control is not falsely flagged.

## 4. Factorial calibration design

Use a staged design rather than an unmanageable full Cartesian product:

1. **Smoke stage:** validate every scenario implementation with known-answer fixtures and small replicate counts.
2. **Screening stage:** use a balanced, predeclared fractional-factorial or space-filling design to identify strong interactions among sample size, segment duration, SNR, temporal dependence, missingness, heterogeneity and site shift.
3. **Qualification stage:** run the frozen critical cells with at least 1,000 Monte-Carlo replicates; use at least 10,000 replicates for the primary null families when a narrow Type-I error tolerance is required.
4. **External confirmation:** apply the frozen pipeline to an authorized independent acquisition/cohort without tuning against its outcomes.

Candidate screening levels (not empirical findings):

- participants: 24, 48, 96 and a larger cohort-sized condition;
- segment lengths: 80, 160 and 320 time points, with sampling-rate and duration semantics recorded separately;
- AR(1) coefficients: -0.30, 0.00, 0.30, 0.60 and 0.80;
- missingness: 0%, 5% and 20%, separately under MCAR, MAR and MNAR mechanisms;
- response fractions: 0%, 25%, 50%, 75% and 100%;
- sites: one-site baseline, site nuisance and held-out-site conditions;
- effect magnitudes: zero plus a preregistered range spanning sub-threshold, minimally meaningful and strong effects.

Do not interpret these values as universal neuroscience operating ranges. They define a transparent synthetic challenge grid whose realism must be justified for each modality.

## 5. Required evaluation outputs

Report each dimension independently. Do not collapse them into a single quality, reliability or consciousness score.

| Dimension | Primary output |
|---|---|
| Type-I calibration | Empirical rejection rate, Monte-Carlo interval, nominal alpha and deviation |
| Detection | Directional power in the preregistered expected direction, two-sided rejection frequency, and wrong-direction significant rejection rate, versus effect dose at fixed Type-I error |
| Estimation | Bias, RMSE and signed error against known latent effect |
| Uncertainty | Confidence-interval coverage and interval width |
| Dose response | Estimated effect and detection curve; uncertainty for adjacent-dose contrasts |
| Multiplicity | Edge-wise FDR/FWER where edge-level claims are made |
| Nuisance robustness | False-positive rate under each nuisance-only null and interactions |
| Heterogeneity | Recovery by response fraction and direction; subgroup calibration |
| Transportability | Participant, site/device and independent-cohort results reported separately |
| Selection integrity | Planted-leak detection, clean-control false alarms and selection optimism |
| Abstention | Correct refusal under insufficient information; false-abstention rate when adequate |
| Data sufficiency | Expected gain from more data, compared with NSI only for compatible precision-fMRI inputs |
| Reproducibility | Exact source, input, configuration, environment and output digests |

For a nominal 5% test, a proposed primary-null engineering gate is that the one-sided 95% Monte-Carlo upper confidence bound for the empirical Type-I rate does not exceed 0.06 (nominal alpha + 0.01), using at least 10,000 replicates per critical null cell. This permits a conservative exact test rather than incorrectly requiring the observed rate to equal alpha from below. Use at least 1,000 replicates in other qualification cells and report Monte-Carlo uncertainty. These are proposed design gates, not universal scientific standards. Power should be assessed at a prospectively defined minimally meaningful effect; 80% or 90% may be adopted as a design target only when justified by the intended inference and error costs. A high-power cell cannot compensate for a failed nuisance-only null.

### Qualification envelope, not a universal score

The final product should be a **claim-scoped qualification envelope** over the conditions in which a measurement method has actually been tested. For each constructor/comparator pair and declared construct, record:

- modality, acquisition and preprocessing versions;
- participant count, usable duration, segment length and temporal dependence;
- SNR, missingness mechanism/rate, nuisance family and site/device;
- responder fraction, direction and smallest meaningful effect;
- Type-I calibration, directional power, uncertainty coverage and bias;
- transportability tier and evidence receipt.

Each envelope cell is marked `qualified`, `failed`, `not tested` or `out of domain`. Do not promote a neighbouring untested cell by visual interpolation. A method-selection policy may choose among estimators only inside the qualified region; outside it, CETB should abstain and explain why. Benchmark both unsafe acceptance of unqualified conditions and false abstention on qualified conditions.

This creates an instrument passport rather than a leaderboard score: researchers can see exactly what a method is trusted to measure, at what resolution and under which acquisition conditions.

For prospective design, expected information gain should also be stress-tested against plausible nuisance priors and acquisition constraints. Freeze predictive distributions before data collection, score them on untouched outcomes with proper predictive scores (for example, log score or Brier score where applicable), and report sensitivity to the prior over nuisance conditions. A high nominal EIG is not valuable if it disappears under modest, defensible nuisance assumptions.

**Direction-aware recovery is now implemented in RCAF report schema 0.2.0.** The legacy `injection_detection_power` remains the overall two-sided significant-difference rate. It is now partitioned into `injection_directional_detection_power` (significant positive paired gaps, the preregistered direction for the positive module-loading injection) and `injection_wrong_direction_rejection_rate` (significant negative paired gaps). A wrong-direction result cannot count as successful recovery. A deterministic unit test covers positive, negative and non-significant cases. The direction expectation is valid for this declared positive-loading generator; a future signed/decrease injection must declare its own expected direction rather than reuse this label.

## 6. Statistical safeguards

- Participants are the inferential unit. Windows, segments, trials and edges are nested observations, not independent participants.
- Use paired participant-level estimands; preserve within-person pairing and condition order.
- Use exchangeability-respecting permutations and participant/site-clustered uncertainty. Do not shuffle time points as if they were independent.
- Use common random numbers for paired estimator comparisons, but disjoint development and confirmatory seed sets.
- For known-direction injections, preregister the expected sign; count directional recovery only when the test rejects in that direction, and report two-sided rejection and wrong-direction rejection separately.
- Keep ground-truth latent networks and injection labels out of the analysis API until scoring.
- Freeze preprocessing, estimator, comparator, thresholds, exclusions and model-selection choices before confirmatory evaluation.
- If a method is selected from candidates, selection occurs inside training data/nested folds; the outer test fold is used once.
- Record failed runs, invalid cells, exclusions and abstentions. Never silently drop a difficult scenario.
- A run that fails its null control is disqualified from interpreting its injection-recovery result.

## 7. Reuse and comparison with the field

CETB should integrate and qualify existing tools rather than recreate their primary functions:

- **PFM-NSI:** reuse the public implementation only for compatible precision-fMRI inputs. Its Python CLI expects CIFTI `.dtseries.nii` on fsLR-32k by default; optional fsaverage6 input requires Connectome Workbench resampling. The inspected ds003171 v2.0.1 release provides BOLD NIfTI `.nii.gz` files and no CIFTI `.dtseries.nii` files, so NSI is not directly applied to that release. A conversion must be independently qualified against NSI's surface/parcellation/preprocessing assumptions before use. NSI is not a general EEG/MEG quality metric and its optional reliability projection is not a substitute for observed repeat measurements.
- **BIDS/OpenNeuro/NEMAR:** dataset structure, provenance and discoverability.
- **fMRIPrep/XCP-D/MNE:** modality-specific preprocessing and signal handling.
- **pyspi:** broad functional-connectivity statistic library and estimator comparison.
- **Published pipeline benchmarks:** use as baselines and pipeline-robustness references; do not claim superiority from a smaller synthetic tournament.

CETB's proposed differentiator is the qualification contract joining known-truth calibration, nuisance-only nulls, repeatability, leakage audits, prospective experiment choice and independent replay.

## 8. Biological validation sequence

1. Complete adversarial synthetic qualification and audit all generated truth labels.
2. **Primary reproduction:** reproduce the published RCAF/WJ and relevant connectivity analyses on OpenNeuro [ds006623 v1.0.0](https://doi.org/10.18112/openneuro.ds006623.v1.0.0), using the exact published code, preprocessing version, participant flow and frozen file manifest. This is the Michigan cohort (26 released participants; downstream analysis denominators must be recomputed from the pinned protocol), not external validation.
3. Run prespecified sensitivity analyses separately from the primary reproduction.
4. **External transportability:** after freezing all choices on ds006623, test the locked pipeline on OpenNeuro [ds003171 v2.0.1](https://doi.org/10.18112/openneuro.ds003171.v2.0.1), a distinct Western University cohort of 17 healthy adults acquired on a 3T Siemens scanner. It has awake, light, deep-sedation and recovery conditions, with resting-state and naturalistic auditory-listening runs. The current dataset description reports CC0 and BIDS 1.0.1; verify the pinned release and its checksums before analysis. The registry records this as a planned independent-cohort/site validation, not completed evidence.
5. Use **resting-state awake versus the deepest harmonizable sedation/unresponsive state** as the primary cross-dataset contrast, conditional on matching operational state definitions and acquisition conditions. Do not assume that a dataset's `deep sedation` label is identical to another cohort's `loss of responsiveness`; harmonize by frozen behavioural/propofol criteria before comparison. Analyse auditory-listening awake versus deep sedation separately; treat light sedation and recovery as secondary trajectory analyses. Never pool rest and task runs or retune on ds003171 outcomes. A prior analysis reported only 10 participants retained for some awake/deep comparisons after motion exclusions, so freeze participant-flow rules and treat wide intervals/inconclusive results honestly rather than interpreting low power as a failed replication.
6. Only after the conventional baseline is reproduced and external analysis is locked, compare Symthaea HDC/CfC/LTC representations as additional candidates under the same folds, estimands, budgets and reporting rules.
7. Keep behavioural report, task performance, physiology, perturbational complexity and phenomenal-experience interpretations distinct. No single proxy or model score establishes consciousness.

## 9. Implementation status and remaining gap

The research kernel now implements:
- deterministic Gaussian-factor time-series generation with participant-specific loadings and stationary AR(1) dependence;
- positive module-loading perturbation before sample-correlation estimation;
- a separate observation-only common-mode factor injected into one repeat while holding latent global/module loadings fixed;
- exact same-observation null, two-sided difference detection, expected-direction recovery and wrong-direction rejection;
- a zero-strength nuisance control that reuses the exact null sample as a known-answer invariant;
- report schema 0.3.0 with separate null, nuisance-only and injection outcomes, plus Wilson intervals.

The common-mode nuisance is the first implemented adversarial nuisance family. Its executable matched-dose sweep evaluates `[0.0, 0.10, 0.20, 0.30]` with an exact zero-strength null control. Nuisance innovations are drawn from deterministic participant/replicate-specific streams separate from the latent-signal RNG; therefore null and intended-injection metrics must remain exactly identical across nuisance strengths, with only the nuisance-related output changing. A separate schema, example, Rust tests and workflow step validate this invariant. The numerical sweep curve is not yet available pending exact-head execution. This family does not model motion, censoring, site/scanner scale shifts, physiological waveforms, parcel dropout, MCAR/MAR/MNAR missingness, nonstationarity, source leakage or a full neuroimaging preprocessing pipeline. It measures the sensitivity of this observed-matrix comparison to one controlled artifact; it does not prove that the metric can distinguish artifact from neural change on real data.

The accompanying `adversarial-calibration-plan.schema.json` and `tools/validate_adversarial_plan.py` validate the plan structure and key semantic invariants: separated development/confirmation seeds, exact null controls, nonzero effect doses, pre-estimation signal-level and matrix-level controls, nuisance-only scenarios that preserve latent truth, and required output dimensions. Thirteen focused plan-validator unit tests were added. The separate Rust tests now also cover direction classification, common-mode nuisance reporting, zero-nuisance equivalence and invalid nuisance strengths. These tests still require an exact-head run to claim CI validation.

Still outstanding: deterministic implementations for the other nuisance families, planted-positive and clean-negative leakage controls, the independent biological reproduction, external-cohort execution and exact-head evidence receipts for the final source head. No biological data have been analysed by this increment.
