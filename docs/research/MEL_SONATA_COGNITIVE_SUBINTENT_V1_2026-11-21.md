## Paradigm shift: hierarchical musical intent

The formal Sonata plan determines **what must be achieved**. The cognitive/FEP path may influence **how** that requirement is realized, but only through a typed capability that maps to an existing, qualified score transformation.

This keeps three things separate:

1. **Formal objective:** the top-level \`SymbolicAction::ReturnOpeningMaterial\` and the exact driving obligation ID.
2. **Cognitive subintent:** the FEP source action, mapped only where the adapter has a concrete supported strategy.
3. **Realization evidence:** exact candidate Score, obligation verification, theory validation, and preservation of the score complement outside the target region.

The FEP action is not allowed to replace the formal objective. An unsupported FEP action is retained as \`UnsupportedShadowOnly\`, with no score or selection effect.

## v1 capability mapping

| FEP source action | Typed subintent | Existing Sonata strategy |
|---|---|---|
| \`RepeatMotif\` | \`RestoreOpeningMotifLiterally\` | \`LiteralRegister\` |
| \`Maintain\` | \`PreserveCurrentReturn\` | \`KeepCurrent\` |
| Other current \`MusicAction\` variants | Unsupported / shadow only | None |

This mapping is deliberately conservative. It does not claim that chromatic exploration, modulation, complexity changes, tension resolution or counterline addition are implemented by a return-motif strategy. Those require their own realizers and proofs.

## Hard gates

A candidate may be selected only if:
- it satisfies the exact bound driving obligation;
- canonical score theory validation succeeds;
- the protected score complement outside the declared target is unchanged;
- the measured candidate refers to the same source realization and plan used to generate the batch.

A known-but-unbound obligation, missing obligation evidence, unsupported request or invalid candidate cannot produce a new score recommendation. The existing musical-policy choice is retained only where the formal gate still permits it; when a bound obligation has no verified candidate, the recommended ID is cleared.

The subintent selector never edits a candidate. It selects one candidate already generated by the deterministic strategy portfolio and independently assessed.

## Counterfactual tests

The new tests cover:

- \`RepeatMotif\` selecting the qualified literal-return candidate when the driving obligation and protected-score checks pass;
- unrelated FEP actions remaining shadow-only and producing identical candidates/selections under the same source score;
- recognized cognitive intent being rejected when no driving obligation is bound;
- an unknown driving obligation failing closed, making every candidate ineligible and clearing the recommendation.

The current test is still a synthetic score fixture. It is not an independent human-preference result, not a proof of general cognitive control, and not a live audio collaboration result.

## Next research steps

1. Add a same-source counterfactual where \`RepeatMotif\` and \`Maintain\` have different, both-valid candidate selections and require different exact Score digests.
2. Add a typed desired-effect model with dimensions for motif identity, register, contour, harmonic function and rhythm. Do not infer unsupported dimensions from one FEP enum.
3. Bind candidate portfolios to source Score, Sonata plan, obligation ledger, model snapshot, renderer and seed digests.
4. Add score-diff certificates that enumerate changed event IDs and prove the protected complement byte-identical.
5. Blind musician evaluation of candidate pairs; keep preference labels distinct from model predictions and outcome-model learning.
6. Only after symbolic controls pass, render the selected Score and test live timing, recovery and human consent.

## Qualification boundary

The exact package workflow checks the real \`symthaea-muse\` crate on top of the workspace repair. A passing targeted test establishes this adapter's Rust and synthetic-fixture behavior only. The whole repository, audio renderer fidelity, musician preference, live human interaction and production model/checkpoint identity remain separate qualification tasks.
