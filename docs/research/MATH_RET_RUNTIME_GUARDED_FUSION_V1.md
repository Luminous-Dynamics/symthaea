# MATH-RET-RUNTIME-001E — Guarded F-Arm Fusion Qualification

Status: draft one-variable successor to guarded S-arm MATH-RET-RUNTIME-001D.

## Experimental discipline

This tranche preserves the candidate artifact, candidate-set digest/count, S and N index manifests, fusion policy, context packer, source-object/materialization policies, budgets and validator stack generated by the guarded S fixture. It changes only the runtime arm from S to the preregistered F fusion binding.

Promotion remains downstream of a qualified #4357 base. Preparing this draft does not convert a queued S run into evidence.

## Positive runtime fixture

Frozen raw channel rankings:

```text
Syntax S:          [a1, a2]
ExactNormalForm N: [a2, a3]
```

Fusion method:

```text
ReciprocalRankFusion
score(x) = Σ 1 / (k + one_based_rank(x))
ExactRational arithmetic
```

Therefore `a2` receives two contributions and ranks first. `a1` and `a3` receive equal one-channel rank-1/rank-2 style contributions as defined by their positions; for the frozen fixture the expected deterministic result is:

```text
[a2, a1, a3]
```

The Rust runtime asserts this sequence. The MATH-RET-TRACE-001A validator independently recomputes fusion from the emitted raw channel rankings and frozen fusion-policy artifact. The packer input must equal the independently replayed fused ranking.

## Membership ordering

Both raw channel rankings pass through `MembershipGuardBackend` before `RetrievalExecutor` can execute deterministic fusion:

```text
S raw IDs ─┐
           ├─ candidate membership gate ─→ fusion
N raw IDs ─┘
```

This is intentionally earlier than deduplication. A source cannot enter one raw channel and disappear during fusion to evade the universe theorem.

## Strong negative fixture

The negative run changes one ExactNormalForm result only:

```text
N: [a2, a3] → [a2, ee]
```

`ee` is outside the exact frozen candidate artifact.

Required result:

```text
RetrievalError::Candidate
materializer calls == 0
staged evidence == 0
committed evidence == 0
negative evidence directory absent
```

## Independent evidence checks

After a positive runtime execution, the qualification driver runs unchanged:

1. MATH-RET candidate-set validation;
2. MATH-RET graph v1.1 validation;
3. MATH-RET trace validation with independent fusion replay;
4. MATH-RET candidate-membership validation over S, N, fused output and packer input;
5. MATH-RET payload actual-byte audit.

The final summary binds exact candidate-set, experiment, F binding, S index, N index, fusion policy, bundle, trace, membership-report and payload-audit identities.

## What a PASS would mean

A PASS establishes runtime-mechanical interoperability for the guarded fusion arm under the same qualified universe and source/payload boundary as S.

It does **not** establish:

- fusion improves retrieval;
- normal-form information helps;
- HDC helps;
- retrieved sources are mathematically relevant;
- any theorem is proved or true;
- any result is novel.

Those are experiment/result-plane questions, not runtime-qualification conclusions.

## Next step after S + F qualification

Only after both guarded runtime arms qualify should actual structural/HDC/exact-normal-form indices implement the guarded backend interface. The first real retrieval experiment should preserve the same evidence chain and preregistered Q0 endpoints rather than change runtime mechanics and representation performance simultaneously.

Production candidate-artifact loading and materializer implementation identity remain a separate hardening track under #4360.
