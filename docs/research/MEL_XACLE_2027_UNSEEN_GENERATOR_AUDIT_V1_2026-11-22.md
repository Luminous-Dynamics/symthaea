# MEL-XACLE-2027-001 — Unseen-generator audio-text alignment audit

**Date:** 22 November 2026  
**Status:** Rust reference audit and synthetic fixtures; no organizer data downloaded, model trained, or challenge submission made.

## External task

XACLE 2027 (ICASSP 2027 SP Grand Challenge / GC-8) asks participants to predict human subjective audio-text semantic-alignment scores. The defining shift is from seen-generation-system evaluation in 2026 to evaluation on audio generated by previously unseen systems in 2027.

Official sources:
- Challenge: https://xacle.org/2027/
- Development dataset: https://github.com/XACLE-Challenge/XACLE_Challenge_2027_development_dataset
- Blind evaluation set: https://github.com/XACLE-Challenge/XACLE_Challenge_2027_evaluation_dataset
- Official baseline: https://github.com/XACLE-Challenge/XACLE_2027_baselinemodel
- TuneJury research/code: https://arxiv.org/abs/2606.17006 and https://github.com/yonghyunk1m/TuneJury

The official schedule lists test data release on 19 November 2026, prediction/system report deadline on 3 December 2026, results on 17 December 2026, and invited paper due on 7 January 2027.

The public 2027 development dataset README describes 7,500 train, 3,000 validation and 3,000 labelled test audio-text pairs. It contains per-listener ratings, listener IDs, and generator model IDs/names. Four native-English speakers rated each training/validation item and eight rated each labelled-test item. The separate blind evaluation repository describes 4,000 audio-text pairs, only wave_file_name and text in the visible metadata CSV, and no public ground-truth scores. Both dataset READMEs instruct participants to email the organizer for access. We have not requested or received the data in this increment.

## Official baseline and what its metrics mean

The official baseline uses frozen M2D-CLAP audio/text encoders and trains a fully connected projector plus scalar score predictor. Its README reports on the inherited labelled test split:
- SRCC 0.5648
- LCC 0.6142
- Kendall tau-b 0.3997
- MSE 3.1847

These scores are on the public 3,000-item labelled test split inherited from the 2026 dataset. They are **not** the 4,000-item blind XACLE 2027 evaluation result and should not be presented as a current challenge leaderboard score.

The baseline's public evaluate.py performs an inner merge by filename. It does not reject duplicate identifiers or explicitly assert exact item coverage before computing metrics; missing or extra IDs can therefore disappear from the scored join. The MEL audit tool makes those integrity failures fatal and reports generator strata.

The CSV schema also needs explicit reconciliation. The organizer's 2027 dataset README names its audio identifier `wave_file_name` and its average target `average_semantic_alignement_score` (that spelling is used in the published README). The released baseline's dataset loader and evaluator use a preprocessed dialect with `wav_file_name` and `average_score`; its inference script emits prediction CSVs with `wav_file_name,pred_score`. These are not one uniform schema. MEL-XACLE-AUDIT accepts either documented identifier alias and either documented target-score alias, but rejects a file containing both alternatives for the same logical field. Reports record the exact columns selected for metadata, target and prediction inputs. The blind evaluation manifest uses the organizer's `wave_file_name`; the baseline inference output uses `wav_file_name`.

## Reproducible audit contract

tools/mel-xacle-audit provides three modes:

1. score: evaluate a prediction CSV against labelled metadata.
2. compare: evaluate a baseline and candidate on the same item set, with a paired item bootstrap interval for the SRCC delta.
3. validate-submission: check the blind submission CSV against the evaluation manifest without expecting or inferring hidden labels.

It validates:
- unique and non-empty wave_file_name values;
- exact ID coverage in both directions (no inner-join loss);
- finite score values in [0,10];
- ID-based joins independent of row ordering;
- SRCC with average ranks for ties, Pearson LCC, Kendall tau-b and MSE;
- model_id/model_name slices and worst-group SRCC only for groups with at least 20 items;
- deterministic paired item bootstrap intervals;
- SHA-256 identities for exact input CSV byte sequences.

The bootstrap unit is the audio-text item, paired between systems. It does not resample listener rows or claim that repeated ratings from the same listener are independent. The group metrics remain descriptive when the number of items per generator is small.

## Paradigm shifts and research plan

### 1. Treat generator identity as an experimental group

A random item split can leak generator-specific acoustics and rendering signatures across train and test. The first generalization gate is leave-one-generator-ID-out validation using the public labelled metadata. Report every held-out generator and worst-group SRCC, not only pooled performance.

### 2. Preserve the listener distribution

The raw per-listener rating CSV should not be collapsed before all analysis. Compare:
- official average-score regression;
- ordinal distributional regression over the 0–10 labels;
- within-listener pairwise ranking to reduce shared-scale assumptions;
- hierarchical listener-severity models that marginalize listener effects at inference.

The test set has more listener ratings than train/validation, so standard errors and listener composition need to be visible. Avoid treating every listener score as an independent audio item.

### 3. Improve representations and interaction

The official M2D-CLAP baseline concatenates pooled audio and text embeddings before an MLP. Research comparisons should include:
- exact official baseline reproduction;
- CLAP-only and MERT-based features where compatible and license-permitted;
- cross-modal interaction layers over pooled or temporal features;
- explicit semantic alignment vs. acoustic-quality auxiliary heads;
- ensembles with uncertainty and out-of-distribution diagnostics.

TuneJury is a relevant contemporary reward-model baseline: its reported 0.7086 pairwise accuracy is on a separate held-out pairwise preference task, not XACLE MOS alignment. It uses frozen CLAP+MERT embeddings and reports a per-system anchor-calibration method for new generators using roughly 100 labelled pairs. That method is relevant only when generator identity and calibration labels are available; the blind 2027 evaluation metadata shown publicly does not contain a generator ID.

### 4. Resist metric exploitation

Use gain, loudness, truncation, silence, channel conversion and non-semantic timbral metamorphic pairs. The predicted alignment score should respond to changes in semantic relation, not exploit volume or generator-specific mastering signatures. When possible, separate alignment, audible quality and technical validity.

### 5. Separate calibration from hidden evaluation

Use validation generator groups to choose hyperparameters and calibration. Freeze architecture, thresholds, model weights, inference settings and output format before processing the 4,000-row blind evaluation list. Do not use hidden labels or submission feedback to tune the model.

## Prospective targets, not achieved results

The first comparator is the official 0.5648 SRCC on the inherited labelled test split, reproduced on the exact same rows and scoring method.

Suggested gates:
- reproduce official baseline results within a predeclared tolerance;
- generator-held-out validation SRCC >=0.60, with every held-out group reported and no adequate-size group below 0.50;
- inherited labelled-test SRCC >=0.62 and Kendall tau-b >=0.44, with paired item-bootstrap intervals and no test-set tuning;
- stretch objective: >=0.65 SRCC on the genuinely unseen-generator blind evaluation;
- disclose LCC, MSE, per-generator performance, group counts, uncertainty and calibration alongside SRCC.

These are goals, not forecasts or SOTA claims. Only the official blind evaluation can establish generalization on the challenge's unseen generation systems.

## Immediate execution limits

The audit crate is model-independent and can be qualified without the challenge data. Exact baseline reproduction and model training require obtaining the official data and model/checkpoint artifacts. The organizers' public READMEs specify email request for the development and evaluation archives. No email has been sent and no dataset has been received in this increment.

## Claim ceiling

Passing tests demonstrates only the Rust audit tool's behavior on synthetic CSV fixtures. It does not establish a trained model, official baseline reproduction, challenge eligibility, hidden-set performance or leaderboard rank.
