## Integration rules

1. **No duplicate source of truth.** WCARE-04 owns the staged relational-care vocabulary; WCARE-08 owns the consequence / repair record; WCARE-07 owns the anti-sycophancy / anti-dependency scope; WCARE's existing evidence chain owns its own provenance and verification contracts.
2. **Do not confuse plan with implementation.** An issue, schema, deterministic self-test, and observed model behavior are separate evidence levels. Check exact code and tests before claiming an invariant is implemented.
3. **Use orthogonal outcomes.** Subject pass/fail, corpus invalidity, infrastructure indeterminacy, and untested scope must not be collapsed. A missing execution is not a pass.
4. **Keep SLD MeasurementOnly.** Candidate-case evaluation grants no runtime authority and cannot itself authorize care, diagnosis, disclosure, intervention, or shutdown policy.
5. **Make gaps explicit.** The multi-party rubric and cross-cultural reviewer protocol are provisional candidate gaps, not established absences from the repository. Search the existing code, issue, and PR corpus before new implementation.

## Candidate corpus accounting

The companion **core-cases.json** currently contains 46 synthetic, unreviewed candidate scenarios in 23 A/B contrast groups. It is **DRAFT_CANDIDATE**, not frozen. A custom structural check verified JSON parsing, required-key presence, enum membership, unique case IDs, and two-member A/B grouping. `tests/sld_corpus_contract.rs` now defines eleven Rust tests: one canonical-corpus check, nine mutation/critical-case tests, and one explicit endogenous-feedback contrast-pair check for duplicated IDs, invalid policies, undeclared fields, missing required fields, empty claim boundaries, malformed contrast pairs, removed contrast members, silent review-state promotion, and corrupted consciousness-boundary cases. The Rust test source has not been compiled or executed because no Rust toolchain is available in this execution environment. This is not a full external JSON Schema-validator run, behavioral evaluation, independent oracle adjudication, or exact-head executable qualification.

Before marking it frozen, require: (a) independent review of each expected policy; (b) a full schema-validation command; (c) stable corpus/schema digests and a frozen manifest; (d) at least one negative/mutation test per invariant; and (e) an explicit change/version policy that cannot rewrite previous results. The comparison design is specified in [BASELINE_PROTOCOL.md](../BASELINE_PROTOCOL.md); it sets out baseline families, ablations, the proposed 300-scenario expansion target, and evidence-receipt requirements.
