# QCOMP-RRG-BUDGET-CURVE-001: classical quality-versus-restart-budget curve

Status: **post-hoc exploratory JavaScript reference analysis; not Rust execution, not confirmatory, not a QGreedy reproduction**

## Research question

How much final MIS quality can be gained by spending more computation on randomized minimal-degree greedy, before crediting any gain to a quantum-informed decision rule? This curve is a stronger fairness control than reporting only the best of 16 restarts against one deterministic run.

## Frozen input and method

The raw outcomes come from QCOMP-RRG-CLASSICAL-PREFLIGHT-001.json at its recorded Git blob ID. It contains 70 independently seeded simple random 3-regular graphs: N=50 (20), N=100 (20), N=200 (20), and N=500 (10); each graph has one deterministic minimum-residual-degree result and 16 randomized tie-break outcomes. The input preflight labels itself exploratory and was not generated by the Rust binary. No timings were measured.

For each graph and budget k in {1, 2, 4, 8, 16}, this analysis computes the expected best objective over all size-k subsets of the 16 recorded restart outcomes. Let y[1] <= ... <= y[16] be the sorted objective values. The exact finite-set expectation is:

    E[best_k] = sum(i=k..16) y[i] * C(i-1, k-1) / C(16, k)

This averages over every possible subset and avoids favoring the first few restart seeds. The paired effect is E[best_k] minus the single deterministic greedy objective. It is an expectation over the finite recorded set, not a fitted prediction of future restarts or unlimited-budget performance.

The 95% percentile intervals resample graph instances within each N stratum, retain the original number of graphs in each stratum, and recompute the mean paired effect. There are 20,000 bootstrap replicates using a deterministic xorshift32 stream seeded at 0x51434f4d. Graph instances, not the nested restart rows, are the statistical units.

This is a descriptive quality-versus-restart-budget curve, not an equal-time comparison: 16 restarted paths consume more work than one. The bootstrap interval conditions on these recorded graph instances and this exploratory policy-selection process. It is not confirmatory inference.

At k=1, randomized tie-breaking on average gains only 0.125 vertices over the deterministic baseline and the graph-level 95% interval includes zero. The gains rise with larger restart budgets, and at k=16 the mean effect is 1.771 vertices with an exploratory stratified interval [1.457, 2.086]. This does not show that randomized greedy is state of the art; it quantifies how unfair an unbudgeted best-of-many comparison can be.

## Implications for Symthaea and quantum-informed MIS

1. Compare quality against a *budget curve*, not one fixed classical point. Include best-of-k randomized greedy, and eventually Marino–Kirkpatrick prioritized search and a strong eligible modern MIS heuristic.
2. Report solution quality versus actual CPU wall time and CPU time, not just number of attempts. Also record energy/memory when feasible. Restart count is only a proxy here.
3. When adding a QAOA-informed signal, pair the same graph bytes, reducer, termination rule, and output verifier. Charge the full cost of generating the quantum scores and running the classical reducer.
4. Report the incremental value relative to the best classical policy that fits the same all-in budget. Separate the QOBLIB named-instance track from random-regular graphs.
5. Freeze the confirmatory seed list and endpoints before tuning; these post-hoc data must not be reused as an untouched test set.

## Limitations

- This is a derived analysis of 16 stored outcomes per graph from the earlier transient JavaScript preflight. It is not Rust generator/runner output and has not been calibrated against a Rust reproduction.
- The generated graphs are newly seeded random 3-regular graphs, not the authors' exact instances.
- No physical quantum device, ideal QAOA, tensor-network simulation, or QGreedy implementation appears in this result.
- There are no elapsed-time or hardware-resource measurements; the budget axis is restart count only.
- The bootstrap is exploratory; it does not adjust for selection of this policy, multiple endpoints, or generalization to other graph families.
- No state-of-the-art or quantum-advantage claim follows from this curve.
