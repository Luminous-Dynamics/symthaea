# PHOT-CTRL-001A: trajectory-derived MIS prior contract

Status: implementation draft; Rust compilation, exact-search integration, QOBLIB runs, and hardware experiments remain unverified.

Parent issue: [PHOT-CTRL-001 #8689](https://github.com/Luminous-Dynamics/symthaea/issues/8689). Related drafts: [MIS QUBO/Ising contract PR #8618](https://github.com/Luminous-Dynamics/symthaea/pull/8618) and [XY-to-Ising dynamics PR #8629](https://github.com/Luminous-Dynamics/symthaea/pull/8629).

## Research question

Do repeated XY-to-Ising trajectory projections contain useful per-vertex information for *ordering* exact MIS search or prioritizing exact-safe proof queries after classical kernelization, once sampling and controller costs are included?

This is a focused test, not a novelty claim for the general quantum-informed reduction idea. qReduMIS already combines classical kernelization with quantum-derived frozen-vertex signals and reports neutral-atom hardware experiments with up to 231 qubits (Schuetz et al., Physical Review Research, accepted 20 July 2026, https://doi.org/10.1103/nh3b-1wv5). The potential difference here is the source of the signal and the investigation of continuous-phase XY-to-Ising dynamics and temporal trajectory features. That difference has to show a measured held-out benefit.

## Contract implemented by trajectory_prior.rs

- Every trajectory attempt must remain in the input ledger, including ambiguous projections, numerical failures, timeouts, and decoding failures.
- Successful projections must have the exact declared vertex count and spins in {-1, +1}; +1 means selected, consistent with the MIS mapping contract.
- Duplicate or blank attempt IDs and malformed spin vectors fail closed.
- Per-vertex selected counts use only valid projections; the valid-projection denominator is explicit.
- Projection yield is valid projected samples divided by all attempts. It is not silently treated as 100%.
- Empirical inclusion frequency is descriptive of the trajectory generator conditional on a valid projection. It is not the probability that a vertex belongs to an optimum.
- A Wilson 95% interval is emitted only when independent restarts are explicitly declared. The interval is for the conditional valid-projection sampling frequency, not optimal-set membership; the flag is a caller-declared assumption and is not independently proven by this module.
- The only policy function returns a deterministic vertex ordering. It cannot fix a vertex, drop a branch, mark an answer optimal, or issue a reduction certificate.

## Policies to compare

1. Degree-only deterministic ordering.
2. Bias-first ordering: prioritize more extreme observed selection frequencies.
3. Uncertainty-first ordering: prioritize less extreme observed selection frequencies.
4. Shuffled-score and seeded-random controls, generated by the experiment driver.
5. A strong classical MIS baseline with the exact same instance and stopping budget.

The prior module intentionally does not claim which policy is better. The current PHOT-BENCH-003 synthetic pilot did not demonstrate robust all-in benefit from branch-order-only priors, including a non-deployable exact-marginal oracle. A continuation must be allowed to return a negative result and terminate the policy family.

## Current 2026 literature that constrains the novelty claim

- QOBLIB, Nature Computational Science 6, 653–671 (published 23 June 2026), provides ten model-independent problem classes, public instances and results, and explicitly emphasizes comparable classical baselines: https://doi.org/10.1038/s43588-026-00991-1.
- qReduMIS describes an interleaved loop in which measured vertex marginals inform frozen-node choices and exact classical reductions continue on the remaining graph. The broad hybrid architecture is prior art: https://doi.org/10.1103/nh3b-1wv5.
- Kim and Yamamoto's 2026 XY-to-Ising continuation result is a classical numerical study of coherent-Ising-machine dynamics on Wishart-planted problems, not a Symthaea result or an experimental hardware result: https://doi.org/10.1038/s41598-026-41315-7.
- QOBLIB's public contributor instructions accept feasible heuristic submissions without claiming optimality; an optimality claim must be supported by the submission's declared bound: https://github.com/ZIB-AOPT/QOBLIB/blob/main/CONTRIBUTING.md.

## Next experiment: trajectory features, not just final-spin counts

A more discriminating hypothesis is that the trajectory's time-resolved behavior is more useful than the final empirical spin frequency. Predeclare candidate features such as:
- per-vertex final-spin frequency and ambiguity rate;
- spin-flip count and last-flip time across a trajectory;
- cross-restart disagreement;
- sensitivity of a vertex to the XY-to-Ising schedule;
- graph-structural features and their interaction with trajectory features.

Use training instances only to select or calibrate features. Freeze the feature set, controller, and compute allocation before held-out confirmation. The first experiment should be software-only using pinned, reproducible trajectory samples. It must not label synthetic samples as physical photonic data.

## Matched experiment design

For each exact graph identity and hash, compare:
- classical reductions + strong classical MIS solver;
- reductions + degree-only controller;
- reductions + shuffled/random controls;
- reductions + trajectory-derived controller;
- full trajectory-guided pipeline including sample generation, transfer, preprocessing, exact-safe proof/search, repair, and independent verification.

Keep the same input bytes, solver settings, budgets, exactness semantics, and verification implementation. A native/deferred problem generator must be a separate track. Store all runs, not just successful runs, and report timeouts, failed/ambiguous projections, objective values, feasibility, proven optimality, kernel sizes, search nodes, proof-query counts, and costs.

For public comparison, pin the exact QOBLIB repository revision and instance digests. Compare with specialist MIS methods such as KaMIS/ReduMIS where build, license, and compatible interface permit; do not treat general MIP defaults or a greedy heuristic as the sole state-of-the-art comparator.

## Acceptance gates

1. Integrate and compile the Rust module with the repository's pinned toolchain; run unit tests and formatter/lints without weakening existing gates.
2. Test ordering policies against an independent exact MIS oracle on every labelled simple graph through n=5, verifying that all exact answers and certification outcomes are unchanged.
3. Add an experiment driver that binds source/configuration, original graph hash, all attempt IDs/outcomes, prior summary digest, solver seed/budget, verifier digest, and raw result digest.
4. Verify every reconstructed candidate on the original graph independently.
5. Run QOBLIB public instances and strong classical baselines with a frozen tuning/confirmation split and graph-level paired statistics.
6. Charge all-in cost including trajectory simulation or hardware cycles, sampling failures, controller execution, transfer, search, repair, and verification.
7. Continue only if one predeclared trajectory feature shows reproducible held-out value beyond degree, random, shuffled, and strong classical controls. Otherwise publish the negative result and stop tuning branch-order-only variants.

## No-claims boundary

This draft implements the statistic/ordering contract and tests, but the Rust code has not been compiled in this environment. No actual XY-to-Ising trajectory was ingested, no QOBLIB instance was solved by this module, and no speedup, SOTA, physical energy advantage, or quantum advantage is claimed.
