# Creditism Capital Formation Benchmark

## Purpose

Define the benchmark that answers the hardest Creditism-specific question: how a system without transferable financial claims coordinates long-horizon productive capacity.

This is not an argument that debt/equity is necessary or that Creditism is sufficient. It is a function-level benchmark.

## 1. Separate the five capital functions

A financial architecture can perform these functions through different mechanisms:

1. intertemporal commitment — resources are committed before returns exist;
2. risk absorption — losses and uncertainty are assigned somewhere;
3. project selection — competing projects are ranked or chosen;
4. resource coordination — labor, materials, energy and capacity are assembled;
5. maintenance/replacement — future upkeep is financed or otherwise guaranteed.

Do not measure these with one investment number.

## 2. Benchmark project classes

Use synthetic projects with known physical production functions:

- short-cycle workshop expansion;
- medium-cycle housing build;
- long-cycle energy infrastructure;
- R&D with probabilistic success;
- infrastructure with uncertain demand;
- productive asset with high maintenance burden;
- failed project with salvage value;
- strategic project with low immediate return and high resilience value.

Each project declares:

- required resources;
- construction duration;
- commissioning date;
- operating life;
- expected and realized capacity;
- maintenance schedule;
- replacement cost;
- uncertainty distribution;
- salvage value;
- external inputs;
- failure states.

## 3. Competing funding mechanisms

For the same project and physical world, test:

- amortizing debt;
- equity/risk-sharing;
- mutual credit;
- project/community allocation;
- Creditism Community Credit allocation;
- direct public/common pool;
- hybrid mechanisms.

Hold the physical project constant.

## 4. Failure localization

Do not report only whether the project was built.

Capture:

- time to resource commitment;
- probability of completion;
- cost overrun incidence;
- who absorbs the overrun;
- completion delay;
- operational capacity achieved;
- maintenance continuity;
- failure-loss allocation;
- concentration created;
- political/governance dependency;
- information requirements.

Possible outcomes:

- funded_and_completed;
- funded_but_delayed;
- underfunded;
- cancelled;
- completed_but_unmaintained;
- completed_but_underutilized;
- failed_with_loss_absorbed;
- unresolved_due_to_missing_information.

## 5. Creditism-specific commitment problem

A Creditism scenario must state the exact mechanism by which a future project obtains resources before it has produced output.

Examples:

- Community Credit allocation;
- pooled community decision;
- group-account commitment;
- staged milestone recognition;
- stewarded productive asset;
- another explicitly declared mechanism.

Never silently introduce debt-like promises under another name.

## 6. Milestone release test

Long projects should be tested as sequential commitments:

proposal -> evidence review -> first allocation -> construction -> milestone -> second allocation -> commissioning -> operation -> maintenance

At each boundary, the governance system can:

- continue;
- pause;
- redirect;
- cancel;
- require new evidence.

The model must record who has that authority and what happens to already committed resources.

## 7. Risk-incidence theorem

Changing the funding mechanism while holding the physical project and stochastic outcomes fixed should change only those risk coordinates causally connected to funding/risk allocation.

Example:

same project cash-flow path + debt -> debt-service exposure
same project cash-flow path + equity -> loss absorption changes
same project cash-flow path + community pool -> collective exposure changes

This is a core positive-control against hidden project changes.

## 8. Long-horizon information stress

Give project selectors incomplete information about:

- future demand;
- construction cost;
- technology;
- resource availability;
- maintenance failures.

Require explicit uncertainty rather than perfect foresight.

Compare whether different financing mechanisms change the amount or type of information needed for allocation.

## 9. Maintenance as a separate service

A completed asset is not equivalent to a functioning asset.

Require explicit:

capital formation != maintained capacity

Test:

- low-observability maintenance;
- deferred maintenance;
- shortage of skilled repair workers;
- replacement shock;
- incentive changes after commissioning.

Creditism's contribution-recognition system should not be allowed to prove project completion while silently assuming maintenance happens forever.

## 10. Common-pool / stewardship boundary

A community-owned asset must declare:

- title/stewardship status;
- eligible users;
- allocation rule;
- exclusion rule;
- maintenance obligation;
- failure response;
- exit/dissolution rule;
- appeal route.

A commons without an operational allocation rule is an unmodeled resource, not a completed institution.

## 11. Benchmark outputs

Report a vector, not a winner:

- capital availability;
- completion probability;
- completion time;
- resource efficiency;
- maintenance continuity;
- loss distribution;
- concentration;
- governance burden;
- information burden;
- resilience;
- transition cost.

## 12. Claim ceiling

A benchmark can show that one declared mechanism performs better or worse on selected synthetic projects under selected assumptions.

It cannot establish universal superiority, political desirability, or real-world adoption feasibility.

## 13. Why this matters

If Creditism can reliably perform these functions without hidden debt/equity semantics, that is a meaningful result.

If it fails, the failure tells us exactly which institutional function remains unresolved.

Either outcome is valuable.
