# VART-002 Component Episodic Provenance v1

Status: **development contract; not a preregistration; no confirmatory or claim authority**.

## Purpose

VART-001 implicated epistemic provenance as a potentially load-bearing mechanism. A
naive response would be to label an entire episodic memory as grounded whenever its input
came from perception. That is semantically wrong: an episode contains both encoded input
and Symthaea's own cognitive response.

VART-002 therefore separates three facts that must never be collapsed:

1. **content provenance** — what epistemic domain a piece of content belongs to;
2. **derivation provenance** — which exact parent objects and transform produced it;
3. **occurrence provenance** — whether an internal cognitive/episodic event was recorded.

`recorded thought` does not imply `true thought`.

## Component identities

For an existing `Episode`, the memory layer derives three domain-separated SHA-256
identities without changing the historical Episode wire format:

- `episode_perception_subject_sha256` — encoded input + event timestamp;
- `episode_cognition_subject_sha256` — internal output + event timestamp;
- existing `episode_subject_sha256` — composite episodic content identity.

The perception and cognition digests must differ even when their raw vectors happen to
share bytes, because they occupy different epistemic roles.

## Composite derivation

`EpisodicComponentProvenance` binds:

- exact perception provenance;
- exact cognition provenance;
- exact composite episode provenance;
- an `EpistemicDerivationReceipt` whose ordered parents are exactly
  `[perception_subject_sha256, cognition_subject_sha256]`.

Composition is never a grounding transition. The composite episode remains derived and
cannot become `PhysicalGrounded` or `DigitalCommitted` merely because one parent is
grounded.

Counterfactual taint propagates from either parent into the composite record while the
other parent retains its own provenance independently.

## Occurrence is a separate namespace

`EpisodicOccurrenceRecord` has its own domain-separated occurrence SHA-256. It records
that a named recorder observed a particular episodic event at a particular event time.

It does **not** mutate `ProvenanceEnvelope`, does not clear taint, and does not authorize
an assertion about external reality.

This permits statements such as:

- "Symthaea actually generated prediction X at cycle N";
- while still rejecting "prediction X was physically true" unless separate grounding
  evidence exists for the predicted content.

## Transactional sidecars

`EpisodicPersistenceManager` owns:

1. composite provenance index;
2. component provenance index;
3. occurrence index.

Rich component attachment preflights both the component and composite views before
mutating either. Conflicts fail closed.

Wholesale replay replacement clears all three sidecars.

## Paired persistence

`EpisodicSidecarBundle` serializes all three sidecars together and binds them to an
externally computed replay-snapshot SHA-256.

Restore requires:

- exact expected raw bundle SHA-256;
- exact replay-snapshot SHA-256 equality;
- successful bundle/schema decoding;
- all checks before mutation of the current persistence manager.

The replay snapshot digest must be generated by the replay persistence layer or another
independent canonical mechanism. It must not be invented by the sidecar bundle itself.

## Shadow mode

None of this authorizes enforced provenance filtering.

Current development use remains behavior-neutral:

`raw recall -> shadow provenance audit -> telemetry only`

Production prediction confidence, proposal generation, authority, action, and replay
selection must remain unchanged until the promotion gate is satisfied on fresh DEVART.

## Promotion boundary

`verify_vart_002_provenance_enforcement_preparation.py` may emit only
`PROVENANCE_ENFORCEMENT_PREPARATION_ELIGIBLE`.

That means only that a bounded **fresh DEVART enforcement experiment** may be prepared.
It does not authorize hidden VART execution, production rollout, confirmatory execution,
or a scientific claim.

The gate requires, among other conditions:

- perception/cognition subject binding complete;
- composite derivation receipts complete;
- no implicit composite grounding;
- legacy `Unknown` behavior preserved;
- transactional sidecar consistency;
- replay replacement clearing sidecars;
- digest-bound paired persistence restore qualified;
- occurrence truth separated from content truth;
- behavior-neutral shadow characterization on fresh DEVART;
- zero hidden VART feedback used for promotion.

## Scientific use

VART-002 should separately measure whether improvements arise from:

- correct content-domain typing;
- taint propagation;
- retrieval filtering;
- derivation traceability;
- occurrence/content separation;
- uncertainty/abstention.

No single "epistemic intelligence" or "world quality" scalar is authorized by this
contract.
