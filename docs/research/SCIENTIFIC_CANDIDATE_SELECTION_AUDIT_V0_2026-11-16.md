# Scientific candidate-selection audit v0

**Date:** 2026-11-16  
**Tracking issue:** #12489  
**External task family:** SciLaws-Bench  
**Implementation:** research/scientific-candidate-selection-audit

## 1. Motivation

SciLaws-Bench separates numeric fit (S_N), scientific validity (S_V) and hidden-structure recovery (S_S). Its current project page reports that the best candidate generated by a system can outperform the candidate it ultimately submits; for one reported model the mean best-generated/submitted S_N gap is 0.14, for GPT-6 and Claude Opus 5.5 it is 0.03–0.04, and 60% of selected winners in the displayed five-candidate groups are evaluator-Pareto-dominated.

These are benchmark-reported external observations, not Symthaea results. They motivate measuring the gap between generation and selection without leaking the evaluator's answers.

Source: https://yiyihum.github.io/SciLaws-Bench/

## 2. Paradigm shift: separate the live decision from the audit

The live selector and evaluator audit have different information privileges.

**Selector side:** candidate identity, development-only predictions/stability, declared complexity, pre-submission eligibility, permitted training/development/predeclared-validation artifacts and costs.

**Evaluator side:** held-out S_N, source-grounded S_V, Parallel S_S, hidden labels, adjudication results and post-submission oracle comparisons.

The Rust API enforces this at the object-graph boundary:
- CandidateSelectionPolicy::select accepts only &SelectorPacket.
- SelectorPacket has no evaluator metric or hidden-truth field.
- SelectionTrace binds task ID, frozen candidate-pool digest, policy ID, consumed evidence IDs, selected candidate/abstention and all-in selector cost.
- audit_submission accepts evaluator outcomes only after the trace is frozen.
- The trace is rejected if it references evidence not in the packet's permitted evidence manifest.

This is not a sandbox/security boundary by itself. Production execution must put the evaluator and selector in separate processes/storage permissions, keep eval/ and hidden simulator state out of selector-visible mounts, and export only the approved evidence projection. The API makes the intended boundary reviewable and testable; it does not prove a hostile process cannot access external files.

## 3. What is implemented

The dependency-free Rust reference:
- validates task, pool, candidate and artifact identities;
- validates SHA-256 string shape and exact candidate-pool binding;
- retains candidate attempts in Ready, failed, timed-out, invalid, rejected or incomplete states;
- makes exact semantic model duplicates visible as groups instead of silently deduplicating them;
- checks selector evidence references against the permitted evidence manifest;
- refuses selection of unavailable or development-ineligible candidates;
- allows explicit abstention with a reason;
- rejects unknown/duplicate evaluator outcomes and metric fields that do not match the pinned task's declared MetricMask;
- keeps failed, timed-out, invalid, incomplete and missing outcomes in the denominator;
- computes evaluator-only strict Pareto domination and the qualified frontier;
- reports per-metric best-valid upper bounds and per-metric regret independently;
- emits a deterministic JSON audit receipt.

The audit deliberately does not implement a new Pareto optimizer, candidate generator, model registry, evidence ledger, scheduler or scientific score authority. The existing selector remains replaceable; this crate checks its information boundary and independently audits the frozen submission.

## 4. Statistical/metric contract

Task metric masks are explicit:
- numeric fit: S_N;
- scientific validity: S_V;
- hidden structure recovery: S_S.

Only metrics declared by a pinned task profile are accepted. All values in the reference fixture use the upstream 0–100 scale. The audit never averages or scalarizes the dimensions.

Pareto dominance requires the same metric mask and is strict: a candidate is dominated only when another evaluator-scored candidate is at least as good on every declared dimension and strictly better on at least one. Incomparable candidates remain on the frontier.

The per-metric best-valid values are separate upper bounds. They may belong to different candidates and are not a jointly attainable "oracle winner". Regret is reported for each metric separately. No overall scientific-intelligence score is emitted.

## 5. Deterministic fixture

The executable reference intentionally chooses candidate A using a development-only score. After that decision is frozen, evaluator-only labels show:
- candidate B strictly dominates A on S_N and S_V;
- candidate C is incomparable with B and remains on the qualified frontier;
- candidate D timed out and remains in the attempt denominator.

The resulting receipt should report:
- four attempted candidates;
- three scored / qualified;
- one timeout;
- candidate A submitted and strictly dominated by B;
- qualified Pareto frontier B, C;
- submitted-to-best-valid per-metric regret: S_N=10, S_V=5.

This is a known-answer fixture demonstrating the audit math. It is not a live Symthaea selection result or a SciLaws benchmark result.

## 6. Tests and acceptance

Twelve authored Rust tests cover:
1. selector API receives only the development packet;
2. evaluator-only artifact IDs are rejected from the selector trace;
3. candidate-pool and task identity are bound;
4. strict dominance and per-metric regret;
5. incomparable candidate preservation;
6. failed, timed-out and missing outcomes remain in the attempt denominator;
7. semantic duplicate identity is reported;
8. explicit abstention when no candidate is development-eligible;
9. exact task metric profile and missing-dimension failure;
10. duplicate/unknown evaluator outcomes fail closed;
11. non-finite metrics and unavailable/ineligible selections fail closed;
12. deterministic JSON receipt preserves axes and denominators.

The exact-head workflow must pass format, tests, strict Clippy and known-answer CLI receipt checks. These checks have not been claimed as passed until CI verifies the exact PR head.

## 7. Next research experiment

After interface qualification:
- pin the exact SciLaws code/task/scorer/dataset revisions and per-task licenses;
- freeze complete candidate pools before selector treatment comparison;
- compare incumbent, fit-only, complexity-penalized and existing qualified Pareto selection on the same pools;
- use only pre-submission development evidence in each live selector;
- independently score the frozen submission, retain every candidate and every failed attempt;
- use evaluator-only results to calculate S_N, S_V, S_S, Pareto domination and per-axis regret;
- repeat by discipline, Type I/Type II, paper lineage and held-out family with matched inclusive budgets.

Proposed target: reduce evaluator-dominated submissions by at least 50% versus the frozen incumbent without degrading any declared metric beyond preregistered task-cluster uncertainty. This is a target, not a result.

## 8. Claim ceiling

Passing this package qualifies only the API boundary, evaluator audit and deterministic fixture. It does not prove a live selector has improved, that the actual Symthaea policy uses this interface, that held-out benchmark scores have improved, or that a new scientific law has been discovered. The upstream data has varied per-task licenses and evaluator-only answer files; no upstream dataset is vendored here.
