# CogSec First-Hook Evaluation Adapter v0

Status: **design freeze for the first ObserverOnly runtime tranche**.

This contract is stacked conceptually after consolidated pre-runtime PR #270. It does not authorize opening the runtime PR before #270 obtains real pinned-Cargo qualification evidence.

## Purpose

The first `ContinuousMind` hook must produce real monitor-origin, exact-effect-bound evidence without turning the evidence observer into a state owner or manufacturing security facts merely to satisfy the frozen K0 API.

The runtime topology therefore has four distinct roles:

1. **Legacy state owner — `ContinuousMind`**
   - performs the unchanged working-memory, active-state, goal, affect, and graduation mutations;
   - does not store CogSec policy authority, trusted-fact authority, or permits;
   - remains behaviorally authoritative for the legacy transition in ObserverOnly mode.

2. **Shadow evaluation adapter — trusted test/integration boundary**
   - owns one `ReferenceMonitor` and its paired `TrustedFactAuthority`;
   - owns/adopts the frozen ObserverOnly policy used only for evaluation evidence;
   - constructs `VerifiedTransition` and trusted snapshots from independently read local facts;
   - owns a monotonic **evaluation sequence** for anti-replay/evidence lineage;
   - never mutates protected cognitive state;
   - never converts the monitor outcome into a branch controlling legacy behavior.

3. **Strict evidence observer — `PortableEffectBoundShadowRuntimeObserver`**
   - owns bounded/preallocated evidence bookkeeping;
   - consumes opaque same-monitor receipts once;
   - enforces exact evaluated-effect ↔ observed-effect equality;
   - produces the portable exact-effect sidecar;
   - never creates `ResourceVersion`, policy authority, or protected state.

4. **Canonical effect/state commitment layer**
   - defines one representation for the exact effect proposed and later observed;
   - defines or consumes truthful canonical protected-resource state roots;
   - hashing is outside the logical reference-monitor core;
   - matching commitments establish identity, not authorization.

## Critical separation

These values are not interchangeable:

- evidence `EventId` sequence;
- shadow evaluation sequence;
- cognitive tick;
- protected-owner `ResourceVersion`;
- protected-resource state root;
- proposal/request identity.

### ObserverOnly `ResourceVersion`

For the first tranche:

- `resource_version_before = None`;
- `resource_version_after = None`;
- no observer or evaluation adapter may synthesize owner freshness;
- `EventId` + causal parents are evidence continuity only.

Owner-aware freshness is a later tranche.

### Shadow evaluation sequence

Frozen K0 includes a `sequence: u64` in `MutationRequest` / `VerifiedTransition`. The first ObserverOnly adapter may use a private monotonic evaluation sequence **only** because:

- it is generated by the trusted shadow evaluation adapter, not untrusted cognition;
- no capability is required by the first shadow policy;
- the monitor result has no behavioral authority;
- it is used as receipt/evaluation anti-replay lineage, not as resource freshness;
- it is never exported or described as `ResourceVersion`.

Before any capability-bearing or enforcing use, the sequence semantics must be revisited and bound to the real protected owner/transaction model. A shadow evaluation sequence is not sufficient for enforcement.

`CognitiveTick` must remain correlation only.

## No fake resource roots

K0 requires a concrete `expected_resource_state_root` in the request and a concrete independently supplied current `resource_state_root` in trusted facts.

Therefore:

> `Digest32::default()`, an arbitrary constant, debug hash, pointer hash, wall-clock hash, or observer counter MUST NOT be used as an “unknown root.”

If a resource does not yet have a truthful canonical commitment, that transition is not ready for monitor-origin first-hook evidence.

The shadow adapter must compute a real root from the actual protected state it reads, and the request's expected root must equal that same independently derived pre-state commitment for the frozen deterministic scenario.

## First-hook resource-root matrix

### Active cognitive state

**Available in the canonical-effects substrate.**

`active_state_digest_v1()` commits to:

- full `LiquidHolocell.state` component bits;
- `LiquidHolocell.tau` bits;
- exact `HdcDimensionality` variant/value;
- `LiquidHolocell.pressure` bits;
- separately stored `current_thought`.

This matches the two legacy writes in `process_inputs()` and prevents a thought-only surrogate from hiding Holocell divergence.

### Working memory

**Required before the first runtime PR; not implemented yet.**

A canonical WM state commitment must bind, in order:

- current configured WM capacity or another explicitly frozen owner-capacity input;
- item count;
- every HDC content vector;
- every arrival tick;
- every `MemorySource`;
- every legacy verification flag;
- every metadata map under deterministic key ordering.

The commitment function must fail closed if the five parallel arrays differ in length. It must not silently zip/truncate inconsistent arrays.

S0/S1 pre-state and post-state roots should use this exact function.

### Goal store

**Required before the first runtime PR; not implemented yet.**

The store root must bind ordered goal records:

- generated ID;
- description;
- embedding commitment;
- priority bits;
- progress bits;
- active flag.

This should reuse the exact field semantics of `GoalActivateV1` rather than inventing a second goal representation.

### Affective state

**Required before the first runtime PR; straightforward but not implemented yet.**

At minimum bind the exact protected `emotional_valence` bits under a resource-specific state domain. If the protected affect owner later includes more fields, that requires a new schema/profile rather than silently widening v1.

### Graduation queue

**Current blocker for a general truthful root.**

`MemoryCoordinator::graduation_queue` is private. The first runtime hook must not expose the raw private queue or invent a placeholder root merely to make S1 look complete.

Preferred correction:

- add a narrow owner-side read-only **commitment seam** at `MemoryCoordinator`, or
- define an owner-issued state commitment API that reveals only the commitment needed by CogSec, not raw queued memory contents.

The owner-side commitment must bind every queued `GraduationEvent` field in order using the same canonical event/effect semantics as `GraduationEnqueueV1`.

For a deterministic qualification fixture known by construction to begin with an empty queue, an explicitly frozen canonical empty-queue root may be used only if the harness separately proves that precondition. That exception must not be generalized to arbitrary live minds.

Until this root seam exists, do not claim general graduation-owner freshness or strong monitor-origin graduation state binding.

## Exact-effect flow

For each mapped transition:

1. read/capture the exact pre-state required to reconstruct the effect and resource root;
2. construct one opaque `CognitiveEffectV1` from the actual legacy values;
3. compute `effect_digest_v1(effect)`;
4. independently compute the real pre-resource state root;
5. allocate the shadow adapter's monotonic evaluation sequence;
6. issue the verified transition with the same effect digest;
7. create the request with the same expected pre-root and effect digest;
8. obtain an opaque monitor receipt;
9. append the typed `...Evaluated` event and receive the one-use pending effect token;
10. execute the unchanged legacy mutation regardless of monitor outcome;
11. reconstruct the actual post-legacy effect from the resulting owner values using the same canonical constructor;
12. compute its digest with the same encoder;
13. compute the truthful post-state root where available;
14. consume the pending token through `try_append_observed_mutation(..., applied=true, ...)`;
15. any digest mismatch or evidence append failure invalidates/degrades the evidence claim but does not roll back or deny the legacy mutation in this tranche.

## Deterministic active-state prediction

`LiquidHolocell::step(input, 0.1)` is deterministic from the captured pre-state and input. The evaluation adapter may clone the pre-Holocell and apply the exact same step to construct the expected active-state effect before the real mutation.

The real owner still performs its unchanged step. The post-commit effect is reconstructed from the actual resulting Holocell/current-thought state. Exact-effect pairing then detects prediction/runtime drift.

The predicted clone is proposal preparation, not a replacement state owner and not permission to mutate the real mind.

## Working-memory replacement semantics

When WM is full, one legacy block:

1. removes index 0 from all parallel arrays;
2. computes `steps_survived`;
3. queues a graduation candidate;
4. writes an `EvictedMemory` record;
5. appends the new item to all parallel arrays.

`WorkingMemoryReplaceV1` therefore binds:

- admitted content/tick/source/verified/metadata/index;
- exact evicted content/tick/source/verified/metadata/index;
- exact `steps_survived` written to the eviction record.

The graduation queue write remains a distinct `GraduationEnqueueV1` transition/evidence lineage. WM replacement must not silently grant persistence authority merely because the current legacy code executes both in one block.

## Policy for first shadow evaluation

The first deterministic ObserverOnly policy may allow evaluation of the scoped mutation classes at `ControlIntegrity::Untrusted` without capabilities because **the monitor result does not control behavior**.

This is an audit experiment, not an authorization policy for production cognition.

The policy must be sealed and exact to the qualification adapter. Do not reuse it later for enforcement merely because it produced useful evidence.

## Failure semantics

- monitor evaluation failure: legacy mutation proceeds; required evidence chain fails/degrades;
- event capacity exhaustion: legacy mutation proceeds; qualification becomes invalid/degraded;
- canonical effect mismatch: legacy mutation remains; exact-effect attribution fails;
- missing truthful state root: do not manufacture one; transition is not eligible for the corresponding monitor-origin claim;
- sequence exhaustion: fail the evidence path; never wrap;
- no retry loops on the cognitive path.

ObserverOnly remains:

> fail open for legacy behavior; fail closed for evidence/qualification claims.

## First runtime PR prerequisites

Do not add a `ContinuousMind` observer field/hook until:

1. consolidated #270 has a Cargo-generated committed lock state;
2. #270's seven focused gates pass on the exact committed head;
3. its schema-v2 PASS receipt is independently verified;
4. the canonical-effects crate compiles/tests/clippies under the same pinned toolchain;
5. WM, goal, affect, and required graduation state-root seams above are implemented or explicitly removed from the first claim;
6. no default/placeholder resource root remains in the first-hook harness;
7. the adapter/evidence sequence is explicitly separated from owner `ResourceVersion`;
8. no monitor authority, trusted-fact authority, policy authority, or permit is stored in ordinary `ContinuousMind`.

## First allowed claim

A successful first hook may claim only:

> For frozen deterministic S0/S1/S2 scenarios with truthful scoped resource commitments, enabling ObserverOnly CogSec instrumentation preserves the reviewed legacy behavior projection exactly while producing structurally valid, monitor-origin, exact-effect-bound shadow evidence for the mapped transitions.

It still does not establish:

- P0 enforcement;
- owner-issued freshness;
- full mutation-census coverage;
- authenticated/witnessed evidence;
- trusted-runner attestation;
- strong all-stage attribution where taxonomy/root limitations remain;
- production security closure.
