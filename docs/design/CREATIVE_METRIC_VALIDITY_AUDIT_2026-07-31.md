# Creative-metric validity audit — 2026-07-31

**Every metric in the creative-quality benchmark is defective in at least one way, and
the benchmark scores a one-pitch metronomic drone above the real system's output.**

| | drone | real output | |
|---|---:|---:|---|
| `composite` | **0.7366** | 0.7349 | drone wins |
| `melodic_coherence` | **0.9141** | 0.7049 | drone wins by 29.7% |

Measured, not predicted — `degenerate_drone_outscores_real_output_this_is_the_defect`
in `tests/creative_regression.rs` re-measures it on every CI run.

## How this audit came about

Repairing one inverted gate exposed the pattern. `onset_evenness` (then named
`rhythmic_regularity`) is `1 − CV(inter-onset-intervals)`, so 1.0 means perfectly
metronomic — and it carried a one-sided **floor** of 0.780. Measured against 23,446
windows of real recorded piano performance, that floor sits above the repertoire
median of 0.607: **90% of real recorded music would have failed the gate.** The
virtuous-sounding name is how it survived review for months.

The obvious question was whether the other four had the same shape. They do, plus two
shapes nobody was looking for.

## Method

Five parallel read-only audits, one per metric, each testing three failure modes:
**saturation** (pinned at an extreme), **direction** (one-sided threshold on a
two-sided quantity), **self-referential baseline** (constant set from our own output).
Every finding then went to an independent agent instructed to **refute** it, defaulting
to refuted when it could not confirm from source.

25 agents, 20 findings, **none refuted**. Several were narrowed and three had line
citations corrected — the refuters were doing real work, not rubber-stamping. Where a
refuter narrowed a claim, the narrower version is what appears below.

## The single most important correction

The audit's own summary — "a drone passes every gate" — is **false**, and this
document does not claim it. The drone passes **3 of 5**. It is caught by
`onset_evenness` (1.0, above the band) and `form_compliance` (0.0).

But `form_compliance` catching it is **luck, not protection**: that metric returns
exactly 1.000 for any composition with an empty analysis window, so
chord-stab-then-silence — strictly more degenerate than the drone — scores its
maximum. It scores 0.0 here only because a perfectly uniform drone has zero
window-to-window variation. A detector that awards the worst possible input full marks
is not detecting degeneracy.

And `onset_evenness` catches it only because the band was made two-sided on
2026-07-31. Under the previous floor of 0.780, the drone's 1.0 was excellent.

## Findings, with evidence

### `form_compliance` — verdict: **SATURATED**

*form_compliance*


**[high / saturation] If any single analysis window contains zero notes, form_compliance returns exactly 1.000 regardless of every other property of the composition — this is a structural guarantee, not a tendency, and it is why the benchmark reads 1.000.**


> creative_bench.rs:258-260 pushes a 0.0 SENTINEL into mean_velocities and mean_pitches for an empty window. 0.0 Hz is not a pitch and 0.0 is not a velocity; these are 'no data' markers injected into ratio-scale statistics. For values [v repeated m times, 0 repeated (4-m) times], CV = sqrt((4-m)/m), minimised when the non-empty values are equal. With m=3 (one empty window of four) all three CVs are >= 0.57735 simultaneously — density from :256, velocity and pitch from the sentinel. Since the weights at :286 sum to exactly 1.0 (0.4+0.35+0.25), combined >= 0.57735, and :289 computes (0.57735/0.5)=1.1547 which clamps to 1.000. With m=2, CV=1.0, capped at :276, combined=1.0, output=2.0 -> 1.000. Two windows empty is likewise unconditional. Mechanism in the actual run: the gate uses MusicalState::default() (creative_regression.rs:80), i.e. harmony_activations=[0.3;8] and arousal=0.4 (lib.rs:247,251). All three '> 0.5' branch tests in plan_form fail, so the form is Binary AB — 2 sections of 2.0s (form.rs:84-89,93,100-101) — while form_compliance imposes 4 windows of 1.0s (:240-241), a 2:1 misalignment. Tempo = 80.0 (lib.rs:385) * 1.2 * 1.09 * 0.88 = 92.08 BPM (rhythm.rs:20-29), so beat_dur = 0.652s and a 4.0-beat chord (instruments.rs:1060) lasts 2.606s. The chord loop at lib.rs:679-737 therefore emits onsets at only t=0.0 and t=2.606 in a 4.0s piece, with every harmony tone stacked at the identical instant ('on the beat, not staggered', lib.rs:728) and no walking bass (lib.rs:708 requires arousal > 0.4; default is exactly 0.4, so false). Section 0 emits only 2 melody notes (lib.rs:542-557: base_notes_per_section=8, density 1.0 from structure.rs:66, energy_level 0.28 raised to 0.3, round(8*1.0*0.3)=2) into its 2.0s span starting at t=0, both landing before t=1.0 at beat_dur=0.652. Window [1.0,2.0) thus receives no chord onset and no melody note. Corroboration that this is structural rather than stochastic: all five benchmark cases share one MusicalState and vary only the seed (creative_bench.rs:755-766), and generate_chord_accompaniment ignores its seed entirely (lib.rs:646, `_seed`), so the accompaniment is byte-identical across all five — n=5 is effectively n=1 for the structural component, which is why the mean is exactly 1.000 with zero variance.


**[high / direction] The metric's global maximum is attained by the most degenerate possible output — all notes at one instant followed by silence — and because the coefficient of variation is permutation-invariant it cannot measure musical form at all.**


> The output is monotone increasing in the CV of window density, window mean velocity and window mean pitch (creative_bench.rs:279-289), with no upper bound short of the cap at :276. Maximum density_cv over 4 windows is achieved by concentrating every note into one window: sqrt((4-1)/1) = 1.732, capped to 1.0. So the formula's optimum is 'put everything in one place and leave three quarters of the piece silent' — the docstring at :234 claims 0.0 = no structure and 1.0 = clear high/low contrast, but the actual argmax is maximal degeneracy. Random placement also outscores deliberate balanced structure: a Poisson layout gives density_cv = 1/sqrt(4) = 0.5 whereas an evenly-weighted ABA design gives density_cv near 0, so the gate rewards the absence of design. The decisive structural point is that CV(x1..xn) is invariant under permutation of its inputs, so ABA, AAB and BAA are scored identically — yet musical form (exposition, development, RETURN) is entirely a property of order. A function that cannot distinguish a recapitulation from a random shuffle of the same material cannot be measuring form; it is measuring 1-second-scale burstiness of onset count, loudness and register, i.e. local texture contrast. The function never reads composition.section and never calls form::plan_form, so it has no access to the section boundaries it purports to check. The crate's own older scorer got this right: critic.rs:127-166 aligns its windows to the real sections via form::plan_form (:128), skips empty sections instead of injecting a 0.0 sentinel (:144-148), and — critically — is explicitly TWO-SIDED, `1.0 - (normalized - 0.4).abs() * 2.0` at :165, peaking at moderate contrast on a stated Berlyne rationale (:164). The newer metric abandoned all three of those properties. Finally the inline comment at :288 claims 'CV > 0.1 starts scoring', but there is no 0.1 offset anywhere in the expression at :289 — scoring starts at CV > 0, evidence that the author's mental model already diverged from the code.


**[medium / self-referential] form_compliance has exactly one behavioural test and it asserts nothing about form, so neither the saturation nor the direction defect could ever have been caught by the suite.**


> creative_bench.rs:985-998 is the only unit test for the function. Despite its name `form_compliance_structured` it composes one piece and asserts solely `score >= 0.0 && score <= 1.0` (:997) — a bounds check that the clamp at :289 makes unfalsifiable. The second reference, :1040 inside `quality_score_bounded`, is the same bounds assertion. Contrast melodic_coherence, which has a genuine discriminative test at :903-910 (`scale_more_coherent_than_random`, asserting a structured input outscores an unstructured one). No equivalent exists for form_compliance: nothing asserts that a structured piece outscores an unstructured one, that a one-note composition should not score 1.000, or that the score is bounded away from its ceiling. This is what let the metric drift from 0.606 (creative_regression.rs:35-36, measured 2026-04-11) to a pinned 1.000 with no test failing anywhere. The regression gate itself (creative_regression.rs:101-108) is a one-sided floor and therefore also cannot observe an upward move to the ceiling — and per the headroom analysis, all plausible regressions push this quantity upward.


**[medium / saturation] The saturation escapes the benchmark: a live cognitive-loop feedback path consumes form_compliance as `1.0 - form_compliance`, so the `complexity` dimension it feeds is pinned at 0.0, and its sign is backwards relative to what the function computes.**


> src/cognitive_loop/cycle_phase_dynamics/mod.rs:867 reads `complexity: 1.0 - quality.form_compliance, // high form = low complexity`, inside the self-listening block at :848-885 that scores each muse export with CreativeQualityScore::evaluate (:863) and maps it to a symthaea_aesthetic::AestheticScore (:865-872). That score is passed to `cm.process_external_score` (:876) and the resulting dopamine_delta is injected back into muse's neuromodulation (:881-885) — a closed feedback loop, not a test harness. With form_compliance pinned at 1.000 per finding 1, `complexity` is a constant 0.0 and carries no information into that loop, while the other four dimensions vary. Separately the sign is wrong on its own terms: the function measures VARIATION (higher CV -> higher score, :279-289), so mapping a high score to LOW complexity inverts the quantity — a piece with maximal density/register/dynamic contrast is reported to the aesthetic system as maximally simple. This is feature-gated (`#[cfg(feature = "creative")]` at :848; `creative` is not in the default set, Cargo.toml:706) so it is not on every build, but it is production code on the `profile-creative` path (Cargo.toml:945-946), and it means the defect's blast radius extends past the regression gate this audit was scoped to.


**Headroom.** The reading is 1.000; the gate is BASELINE_FORM_COMPLIANCE = 0.50 (creative_regression.rs:40) minus TOLERANCE = 0.05 (:29), so it fires below 0.45 (assert at :101-108). Nominal headroom is 55% of the reading. But the reported value is a clamp, so the real question is the headroom in the underlying quantity. Output = (combined/0.5).clamp(0,1) (:289), so the gate fires when combined < 0.225. Because each cv is capped at 1.0 (:276) and the weights sum to exactly 1.0 (0.4+0.35+0.25, :286), combined is bounded in [0,1] — meaning the entire upper half of the metric's own internal range (combined in [0.5, 1.0]) is mapped to the single output value 1.000 and is unobservable. Current combined is somewhere in [0.5, 1.0] and we cannot tell where. So the required collapse before the gate fires is between 55% (if combined sits at 0.5) and 77.5% (if it sits at 1.0). No plausible shipped regression is that large. Worse, the direction is wrong: the regressions this gate most plausibly exists to catch all move combined UP, not down. A synthesis bug that truncates the render after 2 seconds empties two of four windows and forces the score to exactly 1.000 (see finding 1). A bug that drops the chord accompaniment entirely leaves only the melody, which is already bursty (2 notes in section 0 versus 6 in section 1, lib.rs:542-557), raising CV. A bug that halves note count makes the piece sparser and burstier, raising CV. The only change that fires this gate is one that makes output MORE uniform — evenly spread onsets and flattened dynamics. That is the identical defect shape as the onset_evenness inversion that prompted this audit, pointed the other way: a one-sided floor on a two-sided quantity, satisfiable by getting worse. And since the metric is currently pinned, it fires on nothing at all. Historical confirmation: creative_regression.rs:35-37 records form=0.606 on 2026-04-11 when the 0.50 constant was set ~17.5% below it. The metric has since risen 65% to 1.000 and the gate never registered the move — it cannot distinguish "the music got better" from "the composer started leaving a quarter of the piece empty," and finding 1 shows the second explanation is the operative one.


**Degenerate inputs.** Traced through the formula at creative_bench.rs:235-290, the degenerate cases score as follows. (1) SILENCE / zero notes -> 0.000, caught by the guard at :236. This is the ONLY input that scores 0. (2) ONE NOTE, held: notes.len()=1, so n_windows = 4.min(1/2=0).max(2) = 2 (:240), window_dur = 2.0s; W0=[0,2) holds the note, W1=[2,4) is empty; densities=[0.5,0.0] -> cv = 0.25/0.25 = 1.0; mean_velocities=[v,0.0] -> cv 1.0; mean_pitches=[f,0.0] -> cv 1.0; combined = 1.0 (:286); output = min(1, 1.0/0.5) = 1.000. A one-note composition is PERFECT form. (3) ONE CHORD STAB, 16 notes all at t=0.0 then 4 seconds of silence: n_windows=4, counts [16,0,0,0], each cv = sqrt(3)=1.732 capped to 1.0 at :276, combined=1.0, output = 1.000. The single most degenerate non-empty output attains the exact maximum. (4) ALL ONE PITCH, ALL ONE VELOCITY, PERFECTLY METRONOMIC, 16 notes evenly filling 4s: counts [4,4,4,4] -> density_cv=0; window mean velocities all equal -> 0; window mean pitches all equal -> 0; combined=0 -> output 0.000. (5) PURE RANDOM placement (Poisson, lambda=4 per window): density_cv = 1/sqrt(4) = 0.5, velocity_cv (uniform velocities, 4 per window) ~= 0.29, pitch_cv small; combined ~= 0.4*0.5 + 0.35*0.29 + 0.25*0.05 ~= 0.31 -> output ~= 0.62. The resulting ranking is: chord-stab-then-silence (1.000) > random (~0.62) > uniform drone (0.000) = silence (0.000). Two of the four degenerate inputs score AT or NEAR the ceiling, and the one that scores 0 (the metronomic drone) is arguably no worse than the one that scores 1.000. The metric is not merely blind to degeneracy; over most of its range it prefers it.


### `melodic_coherence` — verdict: **INVERTED**

*melodic_coherence (symthaea-muse/src/creative_bench.rs:46)*


**[high / direction] melodic_coherence is globally maximized (0.9141) by a melody consisting of a single repeated pitch, so the gate file's stated purpose - catching a synthesis bug that flattens all notes to one pitch - is exactly the regression it cannot detect; that bug raises the score 29.7%.**


> creative_bench.rs:57 assigns unison p=0.18, the single largest value in the 13-entry table (creative_bench.rs:56-70). creative_bench.rs:76-79 computes semitones = |log2(f2/f1)*12| rounded, so a repeated pitch gives ratio 1.0 -> 0 -> idx 0 -> p=0.18 on every window. creative_bench.rs:90-91 then gives mean_ln_p = ln(0.18) = -1.7148 and normalized = (-1.7148 - (-4.0)) / ((-1.5) - (-4.0)) = 2.2852/2.5 = 0.91407. No other input can exceed this, since 0.18 is the table max. Measured output is 0.705, so the collapse is +0.209 absolute / +29.7% relative, clearing the 0.64 floor (creative_regression.rs:38) by 0.274 and the 0.59 trigger by 0.324. creative_regression.rs:22-23 asserts the opposite in prose: 'a synthesis bug that flattens all notes to the same pitch would destroy melodic coherence.' The doc comment at creative_bench.rs:42-43 invokes Berlyne's optimal-arousal inverted-U ('a good melody balances expectation with surprise'), which requires a two-sided band, but creative_bench.rs:90-92 implements a monotone-increasing ramp in expectedness - the code contradicts its own stated theory on adjacent lines. No test guards this: creative_bench.rs:912-922 (coherence_single_note) asserts only 0.0<=s<=1.0, and creative_bench.rs:903-910 only checks scale > random.


**[high / direction] No gate in creative_regression.rs can fire on a total pitch collapse - I bounded the composite arithmetically and it survives even in the worst case, by 0.0007.**


> Composite weights at creative_bench.rs:410-413 are 0.35 melodic + 0.25 onset + 0.25 emotional + 0.15 form. Under a pitch collapse: melodic -> 0.9141 (finding 1); onset_evenness is untouched because it reads only start_time (creative_bench.rs:118-120), so stays 0.583; form_compliance loses only its pitch_cv term (creative_bench.rs:281,286: combined = 0.4*density_cv + 0.35*velocity_cv + 0.25*pitch_cv, then /0.5 at :289), and since pitch_cv <= 1.0 by the .min(1.0) at :276, form can fall by at most 0.5 of its own score - from the measured 1.000 to >= 0.500, still above its 0.45 trigger, so form CANNOT fire on total pitch collapse either. Worst case over all emotional values: 0.35*0.9141 + 0.25*0.583 + 0.25*0.0 + 0.15*0.5 = 0.5407 against the composite trigger of 0.59-0.05 = 0.540 (creative_regression.rs:41,29). Realistic case (E~0.65, F~0.75) = 0.7407, essentially unchanged from the measured 0.735. Note also that the one metric in the crate that would catch this - critic.rs:56-63 melodic_interest, a unique-pitch ratio that goes to ~1/N on a collapse - is not imported by the gate file at all (creative_regression.rs:25 imports only creative_bench). And melodic_coherence is not merely observed: self_refine.rs:146,157 feeds creative.composite into a seed-search objective at weight 0.25, so among candidates the more repetitive one is actively selected.


**[medium / self-referential] The 0.64 floor is self-referential and the repertoire data that would replace it is already being computed and discarded on one line of the existing calibration harness.**


> creative_regression.rs:35-37 records the provenance verbatim: measured melodic=0.755 on 2026-04-11, 'Baselines set ~15% below measured', giving 0.64 at :38. creative_regression.rs:46-51 already concedes in prose that these four constants 'are self-referential ... regression detectors and nothing more' and names this as the shape that produced the onset_evenness bug - but only onset_evenness was repaired (the band at :63-64 and the two-sided test at :164-185). Meanwhile rhythm_gate_calibration.rs:160 calls CreativeQualityScore::evaluate on every one of the 23,446 MAESTRO windows - which computes melodic_coherence at creative_bench.rs:404 as part of the same struct - and then returns only `.onset_evenness`, throwing the melodic distribution away. The comment on that line even says so: 'Only `onset_evenness` is read'. Caution for whoever runs it: confound 1 at rhythm_gate_calibration.rs:38-42 notes that highest-pitch melody extraction on dense piano writing picks up inner voices, producing an erratic top line; that biases onset_evenness UP (more regular) but biases melodic_coherence DOWN (more large leaps -> idx 12, p=0.07), so the two confounds point opposite ways and MAESTRO's melodic_coherence may well land below the current 0.64 floor.


**[medium / other] The normalisation endpoints do not match the table, making 0.0 and 1.0 both unreachable and the clamp dead code; and the abs()/min(12) reduction discards direction, order and leap size, so a two-note trill outscores a real scale and a four-octave leap outscores a tritone.**


> creative_bench.rs:89's own comment names the true achievable endpoints - 'ln(0.18) = -1.71 (best), ln(0.02) = -3.91 (worst)' - but creative_bench.rs:91 then normalises against -1.5 and -4.0, which correspond to probabilities e^-1.5 = 0.2231 and e^-4.0 = 0.0183, neither of which appears in the table (max 0.18, min 0.02). Consequence: the metric's real range is [0.0352, 0.9141], width 0.879; 8.6% of the top is structurally unreachable and the .clamp(0.0, 1.0) at :92 can never bind. Separately, creative_bench.rs:77 applies .abs() to the signed semitone interval, so a melody and its retrograde, and a melody and its inversion, score identically, and the score depends only on the multiset of adjacent intervals, not their order. creative_bench.rs:78 does idx = semitones.min(12), collapsing every leap of an octave or more into one bin at p=0.07 - so a 48-semitone jump scores 0.5363, strictly above a tritone (0.0352), a major seventh (0.0352), a minor seventh (0.1974) and a minor sixth (0.3124). Traced consequence: an A-B-A-B trill (all M2) scores 0.8670, above the ascending C-major scale fixture at creative_bench.rs:862-877 which scores 0.8012.


**Headroom.** Nominal headroom is the tightest of the four: 0.705 measured, fires below 0.59 (BASELINE 0.64 at creative_regression.rs:38 minus TOLERANCE 0.05 at :29), so a 0.115 absolute / 16.3% relative fall. In the metric's units that is a fall in geometric-mean interval probability from 0.1067 to 0.0801 - a 25% drop. Corrected for the metric's true achievable range [0.0352, 0.9141] (width 0.879, since the -1.5/-4.0 endpoints at creative_bench.rs:91 lie outside the table), 0.705 sits at 76.2% of range and the trigger at 63.1%, so the gate consumes 13.1% of achievable range. That is a genuinely tight gate BY MAGNITUDE. The problem is DIRECTION, not headroom: the set of regressions it catches is the wrong set. Regressions that increase leapiness are caught (a melody of major thirds scores 0.5363 and fires; minor thirds 0.5897 fires; a tritone-heavy melody 0.0352 fires hard). Regressions that increase repetition or stepwise collapse are not merely missed, they RAISE the score toward 0.9141. Mode collapse toward a repeated note is the single most common failure mode of a generative music model and is the one this gate is documented to catch (creative_regression.rs:22-23). Worse, the gate is trivially rescued by a minority of repeated notes: I solved the mixture equation and 14.2% unisons + 85.8% octave-plus leaps clears the trigger, as does 63.1% unisons + 36.9% tritones. So an almost maximally incoherent melody passes if one note in seven is a repeat. Practical reading of the 0.64 floor: it demands a melody dominated by unisons and major seconds (repeats and steps); ordinary skip-based idioms - broken thirds, arpeggios, bugle-call figures - sit below it on their own.


**Degenerate inputs.** Traced all four through the formula. (1) ALL ONE PITCH: every window gives freq_ratio=1.0 -> semitones=0 -> idx 0 -> p=0.18, the table maximum (creative_bench.rs:57,76-79). mean_ln_p = ln(0.18) = -1.7148, normalized = (-1.7148+4.0)/2.5 = 0.9141. This is the GLOBAL MAXIMUM of the metric - degeneracy scores strictly higher than a real C-major scale (0.8012) and 29.7% above measured production output (0.705). It clears the 0.64 floor by 0.274. (2) ALL ONE RHYTHM: melodic_coherence reads only `frequency` (creative_bench.rs:76), never `start_time` - completely blind, score unchanged. (3) SILENCE / empty or single-note melody: early return 0.5 at creative_bench.rs:47-49; 0.5 < 0.59 so the melodic gate DOES fire, and composite = 0.35*0.5 + 0.25*0.5 + 0.25*0.0 + 0.15*0.0 = 0.30 < 0.54, also fires. Silence is correctly caught. (4) PURE NOISE / random wide leaps: the repo's own random_notes() fixture (creative_bench.rs:879-892, all leaps >= 1 octave -> idx 12, p=0.07) scores 0.5363, and a uniform draw over all 13 interval classes scores 0.4906 - both below the 0.59 trigger, so the low end works. CONCLUSION: the metric correctly rejects noise and silence, and is blind to rhythmic degeneracy, but is MAXIMIZED by pitch degeneracy. The floor gate is satisfiable by getting worse in exactly the dimension the metric names.


### `emotional_alignment` — verdict: **BROKEN**

*emotional_alignment (symthaea-muse/src/creative_bench.rs:162)*


**[high / other] In the gated path there is no causal channel from the target ValenceArousal to the composition, so `emotional_alignment` cannot be measuring alignment; the reported 0.769 is a frozen artifact of an arbitrary seed-to-target pairing in a source constant list.**


> creative_bench.rs:754 `run_benchmark(config, state)` takes ONE `state`. Line 766 calls `crate::compose(config, state, *seed)` — the target VA is never passed. The generator signature is `compose(config: &MuseConfig, state: &MusicalState, seed: u64)` (lib.rs:520); nothing downstream (lib.rs:522-627) sees a target. Meanwhile line 767 scores each composition against a DIFFERENT `target_va` drawn from the fixed list at creative_bench.rs:755-761 {(0.5,0.7),(-0.4,0.6),(-0.2,0.2),(0.6,0.3),(0.0,0.5)}. The gates call it with `MusicalState::default()` (creative_regression.rs:96, :182, :212, :241), i.e. valence=0.0, arousal=0.4 (lib.rs:251-252) — constant. So the 5 compositions differ ONLY by RNG seed (lib.rs:569 `sec_seed`), and the target is pure decoration.

Proof that any apparent tracking is chance: I minimised mean distance from a single fixed point to those 5 targets. The optimum sits at ≈(0.0, 0.48) with mean distance 0.3909, i.e. a maximum attainable score of **0.7394** for ANY fixed inferred VA. The observed 0.769 EXCEEDS that ceiling, so the per-seed scatter must be leaning toward the targets — which, with no target→composition channel, it can only do by coincidence. Re-pairing which seed goes with which target (a source-level constant, creative_bench.rs:755-761) would change the reported score without changing one note of music.

The sibling call sites have the opposite defect — a tautology. creative_bench.rs:1830-1833 does `compose(&config, state, 42)` then `ValenceArousal::new(state.valence, state.arousal)`; ABTestPair::generate does the same (creative_bench.rs:2072-2077). There the target IS the generator's own input, and the read-back path is a deterministic if-statement: `state.valence` → `minor_weight = (0.5 - valence*0.5)` → flattens scale degree 4→3 and 9→8 (pitch.rs:410-416) → those exact semitone classes are what lines 196-197 bucket as bright vs dark. That grades the generator on having obeyed its own settings, not on expressing an emotion.


**[high / direction] The valence proxy returns exactly 0.0 — the most favourable value against this benchmark's targets — for every degenerate composition, so the gate is satisfiable by getting worse.**


> creative_bench.rs:192-202 counts only semitone classes {4,9,7} as bright and {3,8,6} as dark. Unisons (0), seconds (1,2), fourths (5), sevenths (10,11) and octaves fall through the `_ => {}` arm at line 198 and are counted as NOTHING. A monotone drone produces only class 0, so major_count = minor_count = 0, `total = (0+0).max(1) = 1` (line 201), and interval_valence = 0.0 (line 202). Constant velocity gives vel_var = 0 → dynamics_valence = 0 (line 213) → inferred_valence = 0.0 exactly (line 215).

0.0 is not a neutral outcome here — it is the single best valence coordinate available, because the 5 targets have valences {0.5,-0.4,-0.2,0.6,0.0} with median 0.0. Traced: (0.0, 0.525) → mean distance 0.3968 → **0.736** (96% of the live 0.769). All-zero velocities → **0.727**. Random pitches → interval_valence → 0 by symmetry → same ~0.74 band.

**Headroom.** There is no CI gate on `MusicVerdict` at all — `creative_regression.rs` gates only `creative_bench`, and `critic.rs` appears in no test file outside its own `#[cfg(test)]` module. So "headroom" here means the five internal thresholds in `apply_music_wisdom` (critic.rs:313-340) plus `MUSIC_STILLNESS_THRESHOLD = 0.01` (critic.rs:211). Their live status on real `compose()` output: (1) `melodic_contour > 0.5 && melodic_interest > 0.5` — UNREACHABLE, contour is hard-capped at 0.333 (finding 4), so the consciousness_level boost is dead code; (2) `rhythmic_regularity < 0.4` — ALWAYS TRUE, the value is pinned at 0.0 with 0.4 of margin and no rhythmic change can turn it off (finding 1); (3) `harmonic_alignment > 0.5` — never fires at the default 0.3, and when it does fire it is reacting to the caller's state, not the music; (4) `voice_balance < 0.3` — would need velocity sd > 0.35 against a measured ≈0.093, effectively dead; (5) `form_coherence > 0.5` — usually fires. So of five "wisdom" rules, one is always-on, one is usually-on, three are dead.
