# LQCD-021M — Rust canonical checkpoint record candidate

This tranche is the dependency-neutral Rust parity layer for the independently executed checkpoint commitment oracle in #2823 / LQCD-021O.

It deliberately does **not** compute SHA-256. `symthaea-particle-physics` still has no direct hashing dependency, and the `sha2` / `Cargo.lock` transition must be generated by the pinned Cargo toolchain rather than hand-edited. The code therefore freezes the exact canonical record bytes and the exact domain-separated preimages that a later qualified SHA-256 layer will hash.

## Exact oracle vectors

The Rust tests bind the complete independent #2823 fixtures, not only selected fields:

- genesis encoded length: `431` bytes;
- genesis checkpoint commitment expected after SHA-256: `e5b439c47911a67ecb9d89cc43debb9d5fe9656c4767b9007a5f1b1ec98c5f3c`;
- successor encoded length: `463` bytes;
- successor checkpoint commitment expected after SHA-256: `84d2328883ae397e179697f364db000180975946aa4b0f38a88d6a6e65b3a6b8`;
- stream ID: `0x3100021d00070000`;
- seed commitment fixture: `48d69193d3fa4b0e9ba5044e097074d06f95889e217e4920dae10badb06c19c4`;
- field digest fixture: `7bd62ca29833be0171a4f3232c03a3edca125aa50b33aeb187e702fb1c8c996b`.

The tests compare all `431` genesis bytes and all `463` successor bytes against the independently frozen oracle hex vectors, then decode/re-encode both exactly.

## Authority surface

`LqcdCheckpointRecordV1` binds:

- campaign subject;
- chain ID;
- checkpoint and update ordinals;
- phase/purpose/ensemble-slot/replica/rank coordinates;
- exact packed stream ID;
- 128-bit RNG word position;
- externally supplied seed commitment;
- canonical field-encoding ID and externally supplied field SHA-256;
- sampler stable ID and revision;
- numerical profile;
- environment profile;
- typed genesis/predecessor state.

`validate_restore_authority` rejects substitution of campaign, chain, stream coordinates, seed commitment, field encoding/digest, sampler, numerical profile, or environment profile. `classify_checkpoint_child` requires exact index succession, exact current-head predecessor commitment, and monotonic update ordinal.

## Domain-separated preimages

The Rust candidate exposes only:

- `seed_commitment_preimage(seed)` = `symthaea.lqcd.seed.commitment.v1\0 || seed`;
- `checkpoint_commitment_preimage(record)` = `symthaea.lqcd.checkpoint.commitment.v1\0 || canonical_record_bytes`.

It does not provide a fake, ad-hoc, or transitive-dependency hashing implementation.

## Stricter Rust enum boundary

The production candidate reuses the already-frozen closed Rust enums `LatticeCampaignPhase` and `LatticeStreamPurpose`. Therefore its decoder rejects unknown phase/purpose codes instead of accepting arbitrary reserved 4-bit values. The existing #2823 oracle vectors use only the defined codes and still match byte-for-byte.

This stricter rejection is a Rust fail-closed implementation constraint; it is **not** claimed as independently established by the frozen #2823 Python oracle. If reserved code extensibility is later required, that requires an explicit versioned schema decision rather than silently broadening V1.

## Evidence status

Source-reviewed candidate only until hosted or local pinned-toolchain Rust qualification executes. Queue/provider starvation is not a PASS and is not a source failure.

## Scientific boundary

This tranche establishes candidate Rust parity for record encoding/decoding, preimage construction, metadata binding, and predecessor/index semantics. It does not yet establish SHA-256 parity, seed-preimage verification, field-byte hashing, atomic persistence, real filesystem durability, ensemble equilibration, final-sample admissibility, or EHK agreement.
