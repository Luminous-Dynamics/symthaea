# Phase 1 Benchmark Results

Real CSVs from Phase 1 harnesses run against **actual downloaded datasets**. These are the week-10 decision-point quantitative artifacts.

## arc_agi2_results.csv

**Source:** [arcprize/ARC-AGI-2](https://github.com/arcprize/ARC-AGI-2) `data/evaluation/` (120 public tasks).

**Harness:** `cargo run -p symthaea --example benchmark_arc_agi2 --release`

**Regenerate:**
```bash
cd /srv/luminous-dynamics/symthaea
SYMTHAEA_ARC2_DATA_DIR=data/benchmarks/arc-agi-2/data/evaluation \
  cargo run --release --example benchmark_arc_agi2 \
  > docs/phase1-results/arc_agi2_results.csv
```

**Columns:** `task_id, num_train, num_test, intra_rule_consistency, predicted_correct, notes`.

**Honest summary (120 tasks):**
- Mean intra-task rule consistency: **0.8485**.
- 49/120 tasks (41%) have consistency > 0.9.
- 0/120 tasks solved — no output-grid generator is wired into the current pipeline (`predicted_correct` is always 0).

**What this tells us:** the `GridEncoder` rule-vector representation is self-consistent within ARC-AGI-2 tasks on average (0.85 mean similarity between training examples' rule HVs). This is a necessary-but-not-sufficient signal for a future predictor: if training examples don't cluster, no downstream generator can exploit them; here they do cluster, so the representation is at least not noise. Actually solving tasks requires the `grid_macro_discovery.rs` stretch (Phase 2 per `plans/2-please-make-precious-fairy.md` WS-C decision rule).

## minif2f_v2_results.csv

**Source:** [yangky11/miniF2F-lean4](https://github.com/yangky11/miniF2F-lean4) — 490 Lean 4 `.lean` files under `MiniF2F/Test/` and `MiniF2F/Valid/`.

**Harness:** `cargo run -p symthaea-lean-bridge --example prove_minif2f_v2 --release`

**Regenerate:**
```bash
MINIF2F_V2_DIR=/srv/luminous-dynamics/symthaea/data/benchmarks/minif2f/MiniF2F \
  cargo run --release -p symthaea-lean-bridge --example prove_minif2f_v2 \
  > docs/phase1-results/minif2f_v2_results.csv
```

**Columns:** `file, path, size_bytes, appears_propositional, lean_accepted, notes`.

**Honest summary (490 files):**
- `appears_propositional = true`: **0 / 490**.
- Files whose names/contents include ℝ, ℕ, ℤ, arithmetic operators, Finset, etc.: **490 / 490**.
- `lean_accepted`: `skipped` for all entries — invoking `lean <file>` on a single miniF2F source without running `lake build` first fails to resolve imports (they're lake-managed Mathlib imports). The scope signal does not depend on these invocations; the `appears_propositional` column is the authoritative Phase 1 reach indicator.

**What this tells us:** miniF2F-v2 is **architecturally out of scope** for Symthaea's Phase 1 propositional Lean bridge. Phase 1 reach: 0%. This is the expected result and is thoroughly analyzed in [`../minif2f-v2-scope.md`](../minif2f-v2-scope.md). The file name patterns (`aime_*`, `algebra_*`, `amc12*`, `imo_*`, `mathd_*`, `numbertheory_*`, …) confirm every problem is in the algebra / arithmetic / number theory realm that requires Phase 2's extended `Proposition` AST and arithmetic decision procedures.

## Raw file patterns observed in miniF2F

A quick pass through `MiniF2F/Test.lean` shows problems like:

- `aime_1983_p1` through `aime_1999_p11`: American Invitational Mathematics Examination problems (real/integer arithmetic).
- `algebra_<identifier>`: real-number algebra manipulations.
- `amgm_*`: AM-GM inequality applications.
- `mathd_algebra_*`, `mathd_numbertheory_*`: textbook algebra and number theory.
- `imo_1959_p1` onwards: IMO problems.

None of these reduce to propositional tautologies; every one requires arithmetic and/or quantification over numeric types.
