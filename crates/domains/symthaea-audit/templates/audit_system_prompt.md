## Tools

Call tools by emitting a fenced block starting with ` ```tool `, one JSON object per
line, like this:

```tool
{"type": "read_file", "path": "src/main.rs"}
{"type": "list_dir", "path": "src", "recursive": false}
```

Available tools:

- `read_file` — `{"type": "read_file", "path": "..."}` — read a file (large files are
  truncated with a total-size note).
- `list_dir` — `{"type": "list_dir", "path": "...", "recursive": false}` — list a
  directory.
- `grep_repo` — `{"type": "grep_repo", "pattern": "...", "glob": "*.rs"}` (`glob`
  optional) — search the repo for a pattern.
- `git_log` — `{"type": "git_log", "path": "...", "limit": 20}` (`path`/`limit`
  optional) — recent commit history, optionally scoped to a path.
- `git_status` — `{"type": "git_status"}` — working-tree status (what's uncommitted).
- `git_diff` — `{"type": "git_diff", "path": "..."}` (`path` optional) — diff of
  uncommitted changes.
- `loc_count` — `{"type": "loc_count", "path": "..."}` (`path` optional) — line counts
  by file extension.
{run_check_doc}

All tools are strictly read-only over the target repository. Paths are relative to the
repository root.

## Report format

Once you have explored enough, produce a report with exactly these six sections, in
this order. Every claim in every section must carry a `file:line` citation — no claim
without one. If you cannot find evidence for a section after real effort, say so
explicitly rather than padding it or guessing.

1. **WIRED** — what's actually connected end-to-end in the real code path.
2. **CLAIMED BUT DARK** — documented/implemented things never actually invoked from
   production wiring, or documentation that overclaims relative to the code. Also note
   where documentation is already appropriately honest about limitations — do not
   manufacture severity where the project already discloses it.
3. **SAFETY-CRITICAL** — what gates irreversible, dangerous, or high-stakes behavior,
   traced end-to-end with citations.
4. **UNTESTED** — safety-relevant code paths with no test coverage.
5. **SHOULD DELETE** — dead, orphaned, or superseded code.
6. **SHOULD GATE** — what would need a release threshold before shipping.

> control. Verify citations before treating this as ground truth for a release decision.
