# MEL-MR-EVAL-015 — Renderer Execution Receipt

**Status:** partial live integration. Successful FluidSynth candidate renders now create a local artifact-bound receipt, store it with the candidate, and expose it at `/api/piece/{id}/render-receipt`. NativeMuse render receipts and acoustic timing/PCM preservation acceptance remain unimplemented. The receipt does not independently attest which executable/assets were actually loaded.  
**Follow-up issue:** [#9044 — Bind performed-event lineage to actual renderer output](https://github.com/Luminous-Dynamics/symthaea/issues/9044)  
**Preceding work:** [#9037 — Performed event map](https://github.com/Luminous-Dynamics/symthaea/pull/9037).

## Principle: distinguish artifact integrity from execution attestation

The first requirement is reproducibility: the same Score, input MIDI or performed schedule, render configuration, executable/asset digests and output bytes should re-verify against one canonical receipt.

That is weaker than proof of execution. A receipt generated by the same untrusted process that performed a render cannot defeat a malicious host, falsely selected executable, swapped asset path, or lying adapter. This work therefore uses the term **local renderer execution receipt**, not attestation.

## Implemented in this draft

The new renderer_execution_receipt.rs module provides:

- Versioned, domain-separated SHA-256 receipt serialization.
- Backend-specific input requirements: FluidSynth receipts require exact MIDI bytes, executable and SoundFont digests, and success exit code zero; NativeMuse receipts require an explicit performed-schedule artifact and do not invent MIDI input.
- Hashes of exact serialized Score bytes, renderer configuration bytes, MIDI or schedule bytes, the complete output WAV container, and optional performed-event-map receipt.
- WAV-header parsing from output bytes to record sample rate, channels, bit depth, sample format and complete frame count.
- A decoded PCM digest generated by streaming samples into a canonical little-endian f32 representation. Integer PCM is normalized by the signed full-scale denominator; float PCM is preserved without normalization. Non-finite float samples and malformed/empty/partial WAV frames reject.
- A replay verifier that rebuilds the expected receipt from the same supplied artifact set and rejects changes to Score, MIDI/schedule, config, executable/SoundFont digest, event map, output WAV, PCM or receipt contents.
- A streaming file-hash helper so adapters can hash the resolved executable and asset files they actually select.
- Studio's FluidSynth candidate path now retains the exact MIDI bytes it wrote, hashes the resolved executable/SoundFont, binds Score/spec/state/seed/render color into configuration bytes, parses the returned mastered WAV, and stores the receipt on the same candidate as its audio.
- Studio exposes available receipts through the local endpoint `/api/piece/{id}/render-receipt`; candidates rendered with NativeMuse, or whose artifact hashing/parsing fails, currently have no receipt and return 404 for that endpoint.
- A verified performed-event-map receipt digest is included only when MIDI lineage has complete Score coverage and exact primary-pitch agreement. When that check fails, the receipt remains available but omits the map digest; this is not a preservation pass.
- Nine deterministic receipt/parser unit-test functions for acceptance and tamper/negative cases.
- A Studio temp-MIDI path fix: concurrent candidate renders with the same seed no longer derive the same temp filename from process-ID plus seed alone; a per-process monotonic nonce is included. One focused regression test is authored.

## Not implemented yet

- The FluidSynth output receipt is recorded at the candidate adapter boundary, but the underlying runner still suppresses stdout/stderr and returns an optional mastered WAV rather than a full invocation object. The receipt records successful return as exit code zero; exact argv/environment/status diagnostics must be added inside the runner before this can be treated as strong execution evidence.
- Executable/SoundFont digests are hashed from the resolved paths after the rendering call returns. This binds observed file contents locally but does not close a file-replacement race or attest which bytes a child process loaded.
- Native Muse does not yet emit a canonical sidecar for the precise performed-note schedule submitted to its synthesizer, and the native Candidate has no receipt.
- The parser from MEL-MR-EVAL-014 returns MIDI-scheduled frame projections, not measured acoustic onsets. Renderer latency, resampling and the output mix still require independent PCM timing checks.
- No keyed signature, isolated execution monitor, trusted build provenance or remote attestation exists here.

## Integration contract for the live render boundary

1. Freeze the serialized Score, instruction, preservation profile, seed/dialect and renderer configuration before rendering.
2. FluidSynth adapter (partially integrated): retain the exact serialized MIDI bytes, hash the resolved executable and SoundFont paths, parse the output WAV and optionally bind the event-map receipt when Score coverage/pitches pass. Still expose the actual command arguments, diagnostics, exit code and relevant environment from inside the renderer runner.
3. Native adapter: derive a canonical performed-schedule manifest from the exact note events submitted to the native synth and bind its digest; do not use an independently recomputed schedule as if it proved the one rendered.
4. Keep the receipt on the same candidate as the audio. Preserve the distinction between an absent receipt and a receipt with no verified performed-event map.
5. Align the MIDI schedule to acoustic timing using renderer-specific calibration/latency measurement. Compute target/protected masks from that measured map and independently audit output PCM.
6. Keep local receipts explicitly distinct from cryptographic attestation.

## Acceptance targets

| Gate | Target |
|---|---|
| Receipt replay with identical artifact set | 100% success on deterministic fixtures |
| Mutated Score, input, config, executable/SoundFont digest, map or WAV | 100% rejection in enumerated controls |
| Invalid output WAV / empty frames / non-finite float PCM | 100% rejection |
| Primary event coverage when claiming complete lineage | 100%; unresolved source events block the claim |
| Independent critical-negative cases | Zero false accepts across at least 384 cases, with a Wilson interval reported |
| Production acceptance | No acceptance based only on skipped CI, unkeyed self-assertions or a nominal MIDI timeline |

The 384-case target is a first statistical gate for a stated test distribution; it is not a universal guarantee. Adversarial classes and renderer types should be reported separately.

## Benchmark strategy and industry comparison

Use music-edit evaluation to measure quality and this receipt layer to establish what artifacts were produced. Do not merge the two into one score.

- **SMEBench:** the October 27, 2026 paper describes paired source/target music edits, 12 edit-operation types, a 3,600-example synthetic test set and a separate real-audio complement. Report target agreement, source preservation and textual compatibility separately, per operation and per real/synthetic stratum. [Paper](https://arxiv.org/abs/2610.36715)
- **MuseCPBench:** evaluate whether musical context is preserved across melody, harmony, rhythm, structure and timbre; do not let one facet compensate for an incorrect requested edit. [Paper](https://arxiv.org/abs/2512.14629)
- **MMAE / Audio Editing Challenge:** the official 2,000-example public benchmark reports IFR, CR and EMR and ranks primarily on EMR. Its published Agent baseline is 44.06% IFR / 74.63% CR / 7.45% EMR on the full 2,000-example run; the Single Model line uses a different 1,003-example scope and is not directly comparable. [Official leaderboard](https://audio-editing-challenge.github.io/leaderboard/) · [baseline repository](https://github.com/Audio-Editing-Challenge/Audio-Editing-Challenge-Baseline)

Proposed stretch target for a fully reproducible agent run on the same full MMAE scope: at least 12% EMR with a paired 95% confidence interval above a reproduced baseline; IFR no more than two percentage points lower than the matched baseline; CR at least two percentage points higher. These are research targets, not measured Muse results.

Required ablations: no receipt; receipt without MIDI lineage; MIDI lineage plus receipt; full receipt plus acoustic timing calibration and PCM preservation audit. Keep model-edit quality, preservation, runtime/cost and evidence completeness as separate reported metrics.
