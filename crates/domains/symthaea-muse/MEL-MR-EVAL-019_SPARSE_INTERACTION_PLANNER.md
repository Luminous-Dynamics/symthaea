# MEL-MR-EVAL-019 — Sparse, Budgeted Musical Interaction Discovery

**Status:** implementation draft stacked on MEL-MR-EVAL-018 / PR #9133.  
**Claim ceiling:** deterministic pair-selection plans over caller-supplied, digest-bound acoustic-support and renderer-routing metadata. No live renderer runs, candidate-recall result, acoustic interaction classification, or SOTA improvement is claimed.

## Research question

MEL-MR-EVAL-018 measures a pairwise interaction with four exact render coalitions. The next bottleneck is selecting which pairs deserve those experiments when a score has hundreds or thousands of events.

With a cached baseline render and cached single-event removals, the render cost becomes:

\[
N_{\text{renders}} = 1 + N + |E_{\text{probed}}|
\]

where \(N\) is the number of source events and each selected pair requires one new double-removal render. Exhaustive pair coverage still costs \(1+N+\binom{N}{2}\). This is preferable to naively rerendering all four coalitions per pair, but only if pair selection does not silently exclude important long-range interactions.

## Paradigm shift: from all-pairs testing to evidence-fed active probing

Treat the problem as three separate stages:

1. **Candidate generation:** determine which pairs are plausible from measured acoustic-support and exact renderer-routing evidence.
2. **Budgeted selection:** select a reproducible subset for actual four-coalition EVAL-018 measurement.
3. **Interaction measurement:** execute the chosen renders and replay-verify the resulting EVAL-018 reports.

The planner never equates “not selected” with “no interaction.” Candidate generation is a prior for allocating experiments, not a causal certificate.

### Candidate evidence

- Conservative acoustic-support intervals should come from replay-verified EVAL-017 influence evidence, not just MIDI note-on/off times. Reverb, instrument release, chorus, convolution tails and mastering can extend well beyond symbolic duration.
- Renderer routing domains should be captured from the exact render configuration: track/bus/effect/master memberships, not guessed from instrument names.
- A pair is a temporal candidate when its conservative support intervals overlap.
- A pair is a routing candidate when both events share a known processing domain, even if their supports do not overlap.
- Any incomplete/unknown route description expands the candidate scope to a global pair universe. This can reduce efficiency, but the planner refuses to infer safety from missing topology.

The Rust planner commits source-score and renderer-profile digests, normalized support/topology input, seed and planner configuration into a deterministic receipt. It checks that support intervals are bounded and that non-empty intervals carry an evidence digest. The planner does not itself replay the referenced EVAL-017 report; an integration adapter must only supply those intervals after successful EVAL-017 verification.

## Selection and audit design

- Temporal-overlap candidates are generated with an interval sweep and a hard materialization cap. Dense cases that exceed the cap fail closed rather than truncating silently.
- Shared routing domains are represented as factored groups. The planner samples pair probes within each group rather than materializing every clique edge (a global compressor/master bus can otherwise create \(O(N^2)\) pair objects).
- Unknown routing creates a global candidate group, explicitly marked in every sampled pair.
- A deterministic seeded sampler chooses group probes; selected candidate pairs are ranked reproducibly, and the hard pair budget is recorded.
- A separate audit sample draws pairs outside the known temporal/shared-domain candidate policy. Audit results can estimate miss risk in that sampled stratum; they cannot establish global candidate recall.
- Every plan reports possible-pair denominators, temporal candidate count, routing-group pair incidences, per-group sampling attempts/underfill, materialized candidates omitted by budget, audit pairs/underfill, selected probes and unprobed pairs.

The seed is for reproducibility, not cryptographic randomness. Plan digests provide integrity, not signed identity or remote execution attestation.

## Implemented in this draft

- `src/interaction_probe_plan.rs` adds strict event-index, frame-interval, digest, domain and config validation.
- Per-event acoustic supports are sorted and unioned before overlap search.
- Temporal overlaps are generated by an interval sweep with a hard pair cap.
- Shared routing domains remain factored while pair probes are sampled deterministically.
- Incomplete routing explicitly widens selection to a sampled global all-pairs candidate scope and suppresses false “non-candidate” audit labels.
- A separate deterministic audit sampler chooses pairs outside the current known candidate policy.
- The plan commits exact inputs/config and replays from those inputs.
- Synthetic tests cover overlap, remote shared-compressor scope, incomplete routing, audit-pair exclusion, cost accounting, invalid evidence/intervals, temporal budget exhaustion and report tampering.

## Scientific controls still required

1. **Remote effect interactions:** non-overlapping events sharing compressor, limiter, chorus, convolution reverb, master bus, instrument voice allocation or stochastic effect state.
2. **Long-tail acoustic support:** compare MIDI interval bounds with measured support under explicit tail thresholds and false-negative costs.
3. **Hidden topology:** deliberately omit one route edge and verify unknown-scope expansion; mutate route graphs without updating digests and require replay rejection.
4. **Non-edge injections:** inject known interactions between pairs classified outside the candidate policy, then verify audit sampling detects the misses.
5. **Dense and adversarial graphs:** dense chord clusters, same-pitch voice stealing, global master effects, 100k-event synthetic stress, pathological interval fragmentation and routing-domain cliques.
6. **Stochastic processing:** common-random-number seeds where supported, repeated null blocks, independent-seed uncertainty runs, and explicit abstention when streams cannot be matched.

## Benchmark matrix

Compare all methods on identical scores, renderer profiles and pair-render budgets:

| Method | Role | Expected trade-off |
|---|---|---|
| Exhaustive all-pairs | Reference ceiling | Ground-truth recall on the benchmark, quadratic render cost |
| Temporal overlap only | Cheap candidate baseline | Misses non-overlap shared-effect interactions |
| Shared-domain only | Topology-only baseline | May over-probe broad buses and miss incomplete topology |
| Random pairs | Budget-matched baseline | No structural prior; useful calibration of candidate value |
| Combined support + topology | Proposed v0.1 | More targeted probes with explicit unknown-scope widening |
| Adaptive uncertainty/information selection | Future work | Allocates later renders using measured interaction evidence while preserving audit exploration |

### Core metrics

- Pairwise interaction recall and precision against exhaustive synthetic truth.
- Recall-vs-render-budget and area under the recall-cost curve.
- Detection yield per incremental double-removal render.
- Audit-discovered candidate-policy miss rate with binomial confidence intervals.
- Recall stratified by overlap, effect topology, long-tail duration, polyphony, event density and renderer family.
- Candidate graph materialization time, sampling time, peak memory, plan size and deterministic replay cost.
- Abstention/underfill rate and exact denominator accounting.
- Downstream EVAL-018 calibrated true-positive/false-positive rate, reported separately from candidate recall.

Use score/render-configuration clusters for confidence intervals; individual pairs from one score are not independent. Publish the full cost curve and all strata. Never compare a 95%-recall point against an exhaustive system with a different render budget without showing the full curve.

## Proposed gates (targets, not results)

- 100% exact replay of deterministic plan artifacts.
- 100% rejection of malformed IDs, unbounded intervals, missing support digests, invalid route domains, altered configs and tampered receipts in the enumerated synthetic suite.
- 100% global-scope widening when any route membership is declared incomplete.
- No unprobed pair reported as non-interacting.
- Stretch target: at least 95% held-out pairwise interaction recall at no more than 50% of exhaustive pair-render cost, separately in each held-out renderer/effect family. This target must be revised if the benchmark's base rates or confidence intervals make it statistically unsupported.
- Report false-negative bounds from the independent audit sample; a small audit sample is not evidence of high recall.

## Industry comparison

SMEBench and MMAE are necessary external evaluations for music-editing quality and preservation, but neither provides ground-truth per-source-event factorial interaction labels. Pairwise interaction discovery therefore needs a public synthetic microbenchmark with transparent renderer/effect recipes, exact coalition artifacts and an exhaustive reference evaluator. Product-quality results must remain separate from this microbenchmark.

At the time of this protocol (October 30, 2026), SMEBench reports a 3,600-example paired synthetic test set covering 12 musical edit operations plus a real-audio complement. MMAE's public test package contains 2,000 examples and 17,741 atomic rubrics; its challenge leaderboard/hidden set is scheduled to open November 10, 2026. These measure edit target agreement, instruction following and preservation, not event-pair interaction recall.
