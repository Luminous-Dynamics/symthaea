# DASTARK Migration: Winterfell → Miden VM

## Problem

Winterfell (Meta, v0.13.1) explicitly does NOT provide zero-knowledge.
The July 2024 Haböck/Kindi paper proved this rigorously — STARK proofs
generated by Winterfell may leak information about secret inputs.

For consciousness tier attestations, this means a verifier could potentially
extract the agent's actual Phi score from the proof, defeating the privacy
guarantee of "prove Phi >= threshold without revealing Phi."

## Decision

**Use Miden VM (Polygon, v0.22.1)** — the only production-grade ZK-STARK
that explicitly supports secret/nondeterministic inputs via an advice provider,
hiding private data from verifiers while proving the computation.

**STARK-family only. No SNARKs** (no Groth16, no arkworks, no Halo2).

## Evaluation Summary

| Library | ZK? | WASM Verifier | Proof Size | Maturity |
|---------|-----|---------------|------------|----------|
| Winterfell (current) | NO | yes | ~50KB | Production (non-ZK) |
| **Miden VM** | **YES** | **yes (no_std)** | **80-136KB** | **Production** |
| Stwo (StarkWare) | Ambiguous | yes | <1KB (claimed) | Beta |
| RISC Zero | yes | partial | ~200KB | Production |
| Plonky3 | yes | untested | ~45KB | Alpha |
| ministark | no | yes | ~50KB | Research |

### Why Miden over alternatives

1. **Actually zero-knowledge**: Advice provider explicitly hides private inputs
2. **WASM verifier**: `miden-verifier` compiles to `wasm32-unknown-unknown` in `no_std`
3. **Production**: Used in Polygon Miden rollup (real money at stake)
4. **Pure Rust**: No C/C++ dependencies, no FFI
5. **Reasonable proof size**: 80-100KB for consciousness range proofs

### Why not Stwo

Stwo's ZK masking status is unconfirmed. StarkWare is focused on Starknet
rollup performance, not general-purpose ZK. Reconsider when ZK guarantees
are formally verified.

### Why not RISC Zero

RISC Zero proofs are ~200KB (exceeds budget) and the WASM verifier is
incomplete. The RISC-0 integration in health-zkp is already structural-only.

## Migration Plan

### Phase 1: Miden Assembly Program (1 week)

Write a Miden Assembly program (~20 lines) that:
1. Takes secret input: `phi_score` (via advice provider — never revealed)
2. Takes public input: `threshold`, `score_commitment`
3. Computes: `phi_score >= threshold`
4. Verifies: `hash(phi_score) == score_commitment`
5. Outputs: boolean result

```miden
# Consciousness tier range proof
# Secret: phi_score (advice stack)
# Public: threshold, commitment (operand stack)
proc.verify_consciousness_tier
    # Push secret phi from advice stack
    adv_push.1
    # Duplicate for commitment check
    dup
    # Check phi >= threshold
    gte
    # Verify commitment: hash(phi) == expected_commitment
    # ... (Rescue Prime hash)
end
```

### Phase 2: Rust Integration (1 week)

1. Add `miden-vm = "0.22"` to `mycelix-zkp-core/Cargo.toml` (behind feature flag)
2. Create `src/miden_consciousness.rs`:
   - `prove_consciousness_tier_miden(phi: f64, threshold: f64) -> MidenProofResult`
   - `verify_consciousness_tier_miden(proof: &[u8], threshold: f64, commitment: [u8; 32]) -> bool`
3. Keep Winterfell as fallback (feature `backend-winterfell` = non-ZK fast path)
4. New feature: `backend-miden` = ZK path (default for production)

### Phase 3: Attestation Type Update (2 days)

1. Increase `MAX_CONSCIOUSNESS_PROOF_SIZE` from 50KB to 150KB
2. Add `proof_system: ProofSystem` field to `ConsciousnessAttestation`:
   - `ProofSystem::WinterfellStark` (legacy, non-ZK)
   - `ProofSystem::MidenZkStark` (new, ZK)
3. Verifier dispatches to correct backend based on `proof_system`

### Phase 4: Governance Integration (2 days)

1. Update `verify_consciousness_gate()` to accept Miden proofs
2. Miden verifier runs in WASM (zome-side verification possible)
3. Remove off-chain verification indirection

## Proof Size Budget

| Component | Winterfell (current) | Miden (target) |
|-----------|---------------------|----------------|
| STARK proof | ~50KB | ~80-100KB |
| Score commitment | 32 bytes | 32 bytes |
| Metadata | ~200 bytes | ~200 bytes |
| Dilithium5 signature | ~4.6KB | ~4.6KB |
| **Total** | **~55KB** | **~105KB** |

DHT storage impact: +50KB per attestation. Acceptable given 24h TTL
(attestations expire and are not retained indefinitely).
