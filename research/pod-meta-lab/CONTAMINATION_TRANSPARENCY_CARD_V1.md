# POAR Contamination Transparency Card v1

**Status:** preliminary / research-only disclosure  
**Date:** 2026-10-31  
**Benchmark:** Proof-Obligation Adaptive Reasoning (POAR)  
**Implementation:** `research/pod-meta-lab` in the Symthaea repository  
**Purpose:** disclose what is known, unknown, and not yet audited about benchmark contamination and reproducibility.

This card follows the five disclosure dimensions in Nourbakhsh et al., *Are LLM Benchmarks Already Contaminated?* (GEM 2026): training data, decontamination, evidence provided, instruction-fine-tuning (IFT) stage, and reproducibility. The review distinguishes exact, syntactic, semantic, and task-level contamination (T1–T4), and warns that no one detector reliably covers every tier. Absence of contamination evidence is not evidence of absence.

Reference: https://aclanthology.org/2026.gem-main.50/

## 1. Training data

| Field | POAR disclosure |
|---|---|
| Benchmark corpus | Current v1 graph cases are synthetic, fixed-template records generated by the Rust harness. There is no external natural-language corpus in these fixtures. |
| Generator publication | Generator source is public in this repository. The fixed templates and test logic are therefore visible to anyone with repository access. |
| Model pretraining corpora | **Not known to benchmark authors for third-party models.** Must be supplied by each model provider when available. |
| Model pretraining cutoff | **Not known for third-party models.** Record provider-reported cutoff and whether it is independently auditable. |
| Deduplication of model training data | Provider-specific; **not verifiable by POAR authors** without corpus access or provider evidence. |
| Training-token totals | Provider-specific; not known by POAR authors. |
| Symthaea model/agent exposure | The research harness and its deterministic templates are public from publication. Any model subsequently trained on this repository may have task/template exposure. A public-source checkout is not an uncontaminated evaluation. |

**Consequence:** the checked-in deterministic suite is for contract/conformance testing, not for a headline benchmark score. Do not publish its performance as evidence of generalization to unseen proof graphs.

## 2. Decontamination and test-set protection

No formal T1–T4 audit has yet been run against any evaluated model's training corpus, instruction-tuning data, preference/RL data, or inference-time cache.

| Tier | Mechanism | Current POAR state | Required audit |
|---|---|---|---|
| T1 exact | Exact or near-exact case/answer overlap | Not audited; source is public | Exact IDs, content digests, and n-gram overlap against accessible training/evaluation corpora |
| T2 syntactic | Reordered, paraphrased, retokenized, or reformatted cases | Not audited | Canonicalized structural matching and controlled paraphrase probes |
| T3 semantic | Equivalent proof/evidence structures with different surface forms | Not audited | Graph-isomorphism / semantic-family matching and paraphrase challenge sets |
| T4 task-level | Learning the task templates or answer strategy | **Known exposure risk:** current deterministic templates are public | Hold out generator families, operators, graph motifs, mutation compositions, and seeds; use post-publication sealed test generation |

### Required protection before confirmatory leaderboard use

1. Keep the confirmatory test seed, oracle, and source-family manifest outside the model/planner workspace.
2. Generate test artifacts after freezing the candidate model, prompts, and training-data cutoff whenever practical.
3. Expose only planner-visible cases to the evaluated system; never give it oracle labels or evaluator access.
4. Run the evaluator in a separate process and preferably a separate job/security boundary. The current `GraphSuite` API hides labels from `PlannerCase`, but the in-process oracle is **not** a secure boundary.
5. Rotate generator templates and held-out graph families; retain retired suites for reproducibility but do not use them as the sole live test.
6. Report which tiers were tested, the access assumptions, detector sensitivity, and failure modes. Do not report “contamination-free” unless the evidence supports that narrow claim.

## 3. Evidence provided

Current evidence is limited to source-level controls:
- Oracle truth labels are not fields on planner-facing `PlannerCase`.
- Development, calibration, and test have disjoint source IDs and source-family IDs by construction.
- Source IDs vary by seed, while family IDs remain stable within a split for cluster-level analysis.
- Development/calibration/test chain depths differ (8/32/64 claims) to avoid presenting identical depth distributions across splits.
- Same-seed/same-split determinism is tested.
- Mutation tests preserve the oracle label while changing visible polarity, time, scope, authority, integrity, lifecycle, or source-independence group.
- Retraction testing checks invalidation of dependent claims and stability of an unrelated claim.

Not yet provided:
- No model corpus inspection, membership-inference audit, likelihood audit, semantic-contamination audit, or post-training exposure audit.
- No independent security review of oracle isolation.
- No externally adjudicated contamination estimate.
- No trained-model benchmark results.

These controls reduce some obvious leakage channels; they do not establish absence of T1–T4 contamination.

## 5. Reproducibility

| Field | Current protocol |
|---|---|
| Generator language | Rust |
| Generator source | `research/pod-meta-lab/src/graph.rs` |
| Standalone manifest | `research/pod-meta-lab/Cargo.toml` |
| Current package dependencies | Zero third-party dependencies |
| Rust toolchain target | 1.96.0 in the focused GitHub Actions workflow |
| Seed | Explicit generator argument; same seed + split must reproduce identical planner cases |
| Split | Development / Calibration / Test |
| Case output schema | Rust structs in `graph.rs`; external artifact contract / process isolation is tracked in issue #9360 |
| Prompts / few-shot | Not applicable to synthetic fixture generator; must be frozen and recorded for each language-model arm |
| Sampling parameters | Must be recorded per model arm; deterministic synthetic fixtures do not specify model decoding |
| Scoring | Recursive synthetic oracle; per-case metrics; no composite intelligence score |
| Metrics | Disposition correctness, false closure/refutation, proof-path validity, citation completeness, temporal coverage@3 / precision@3, source admissibility, retraction stability, and resource metrics when a model runner exists |
| Variance | Use multiple seeds and cluster confidence intervals by source family and generation template; one deterministic seed is not a statistical result |
| Exact run receipt | Must include code SHA, toolchain, generator version, seed, split, artifact digests, evaluator SHA, model/checkpoint ID, prompt/config digest, and hardware/runtime profile |

**Current qualification state:** tests are authored but have not yet been compiled or executed in the authoring environment. A focused push-triggered qualification workflow has been committed; no pass is claimed until its exact-head result is independently inspected.

## Release rule

POAR v1 can be described as a synthetic scheduler/proof-graph conformance harness. It must not be described as:
- a contamination-free benchmark;
- a secure hidden-test set;
- an independently verified formal proof engine;
- a model evaluation or SOTA result;
- evidence of general reasoning superiority.

The confirmatory benchmark release requires the evaluator boundary, artifact digests, held-out generator families, model-side exposure disclosures, and exact-head qualification.

---
**Review principle:** disclose known exposure and unknown training provenance. Do not turn missing data into a zero-contamination claim.
