# JEPA observed-transition supervision and action alignment — 2026-11-01

## Change summary

The previous cognitive-loop JEPA integration trained on a tuple assembled inside the planning phase:

- source: current CfC input array;
- target: the multi-scale CfC prediction approximation;
- action: the previous cycle's FEP action index.

That tuple was temporally inconsistent and self-targeted: its source was the current observation, its action belonged to the preceding transition, and its target was generated by the CfC model rather than independently encoded from a future observation.

The new integration stages a real current input, binds the FEP-selected action after the action-selection step, freezes the action-conditioned latent prediction, and resolves/trains that transition only when the next actual input arrives.

## Temporal contract

For observation/cognitive cycle t:

1. The current encoded sensory input is x_t.
2. Before overwriting the pending transition, planning resolves the previous tuple (x_{t-1}, a_{t-1}, z_hat_t) against the current real x_t.
3. The same current x_t is staged as the source for the next transition.
4. FEP selects action token a_t.
5. JEPA binds a_t to x_t and computes z_hat_{t+1} immediately. The predicted latent is frozen and is not recomputed after seeing x_{t+1}.
6. At cycle t+1, the actual compressed sensory input x_{t+1} becomes the target encoder input and trains the frozen tuple.

This is now an observed-transition objective:

    z_hat_{t+1} = predictor(context_encoder(x_t), a_t)
    z_star_{t+1} = target_encoder(x_{t+1})
    loss = cosine_loss(z_hat_{t+1}, z_star_{t+1}) + variance_penalty

The prediction is computed at action-selection time; the target is an independently acquired next-cycle input. It is not the current CfC prediction approximation.

## Implementation

JEPA engine API:
- stage_transition_source(x_t): validate dimensions/finiteness and stage the exact source.
- condition_pending_transition(a_t): validate action range, compute/freeze context and predicted latents, and charge prediction energy immediately.
- resolve_pending_transition(x_{t+1}, lr): validate the observed target, train predictor/context, update EMA target, and update latent-variance telemetry.
- discard_pending_transition(): explicitly drop an incomplete pair and increment the dropped-transition counter.
- pending_prediction(): read-only view for pre-observation forecast diagnostics.

The cognitive loop now stages x_t in the CfC planning phase and binds the selected FEP action after FEP action selection. The training target is the subsequent actual input array. The old current-input / predicted-CfC-output / stale-action call was removed.

## Integrity and cost controls

- Invalid input dimensions, non-finite source/target values, invalid action IDs and invalid learning rates are rejected.
- A pending source cannot be silently overwritten.
- A transition cannot be conditioned more than once.
- A missing action causes an explicit drop rather than action-free or stale-action training.
- A target validation error preserves the pending transition for the caller to explicitly retry or discard.
- Prediction energy is charged when the action-conditioned forecast is created, even when no scoreable future observation arrives.
- A serde-default telemetry counter records transitions dropped because no valid action was bound.

## Tests added

- actual next observation resolves the pending transition and advances training telemetry;
- two action IDs create different frozen predictions for the same source;
- missing action is counted as a dropped transition and does not update weights;
- invalid action and target dimensions fail without consuming a valid pending pair;
- an unresolved transition cannot be overwritten or conditioned twice.

These are unit-level contract tests; no exact-head CI pass is claimed until the focused GitHub workflow completes.

## Action semantics, time alignment and claim boundary

The current cognitive-loop caller binds the FEP-selected action index. This fixes the previous source/action/target misalignment and makes JEPA depend on the action token selected after the source observation. It does not by itself prove that the token was executed as an external actuator command.

This version is **one cognitive-loop transition per observation**. It does not yet pass elapsed duration or action hold time into the JEPA predictor. If observations arrive at irregular intervals, the same action token may correspond to different physical durations. A future physical adapter should add an explicit duration/horizon input and validate event-time alignment instead of assuming equal time steps.

For a physical/action-conditioned world-model claim, the environment adapter must:
- bind the FEP action ID to the canonical executed command and action-space version;
- record action dispatch/acknowledgement, source timestamp, next-observation timestamp and the transition interval;
- reject, invalidate or explicitly mark unexecuted/overridden actions;
- ensure the next input is actually subsequent sensory evidence from that interval;
- include elapsed duration / action hold-time in the predictor or stratify evaluation by it.

Until that adapter is independently verified, describe this as FEP-action-token-conditioned observed-transition learning, not as physical counterfactual fidelity or a deployed action-conditioned visual world model.
