**Status:** research implementation draft; source authored, not yet compiled or executed.

## Purpose

This standalone Rust crate provides two narrow GameBench-specific capabilities:

1. **Decision-sufficiency scoring over matched causal twins.** It identifies the action intersection that remains optimal across evaluator-supplied compatible worlds. A candidate is not required to identify a hidden mechanism when the terminal action is invariant across all compatible in-family worlds.
2. **Transition-event protocol validation.** It validates an environment-produced world-mutating event against an intervention contract and current episode progress, then emits a domain-specific transition receipt and advances the public progress record.

It does not implement a second Bayesian posterior, EVSI calculator, robust minimax planner, sequential policy oracle, general benchmark-run ledger, cryptographic signature verifier, or process sandbox.

## Important boundaries

- The manifest and its loss tables are evaluator-only. `candidate_view()` produces a reduced initial view; it is not a security boundary.
- Compatible-world support must be generated by the evaluator and supplied to the scorer by an independently permissioned evaluator process.
- The transition validator checks structural consistency, action/intervention binding, side-effect class, monotonic timing, declared outcome vocabulary, pre-state digest continuity, replay identifiers, and cost budgets.
- The validator **does not authenticate** the environment event or trace digests and does not prove simulator fidelity. A trusted executor/verifier must authenticate the event stream before this adapter is called.
- This domain transition receipt is not a replacement for #10314 canonical run accounting.
- Read-only probes remain the responsibility of PR #14193. World-mutating actions must not be passed through that bridge.

## Implemented source surface

- Matched-world manifest validation: shared initial observation digest, nuisance digest, legal-action vocabulary, declared mechanism variants, and bounded terminal losses.
- Action-equivalence classification from per-world optimal-action sets using a declared tie tolerance.
- Candidate mechanism-set coverage and false-unique scoring.
- Out-of-family compatible worlds force `Unresolved`; in that case the adapter does not report a common-optimal action as established.
- Candidate selected-action regret by compatible world, with worst-case/mean summaries withheld when out-of-family support remains.
- Transition records bind episode, invocation, intervention, action, issue/apply/observe steps, before/after observation digests, outcome, actual cost, event digest, and trace digest.
- Fail-closed checks for stale/replayed events, wrong action/intervention, read-only/unknown side-effect classes, early/late result, mismatched pre-state, unknown outcome, missing source commitments, and cost violations.

## Authored tests and claim ceiling

The crate currently contains 20 authored Rust tests. They are **not yet executed**. The authoring environment used for this change does not have `rustc` or `cargo`; exact-head CI is still required.

Passing these synthetic tests would qualify only the adapter's local protocol behavior. It would not establish:
- authenticity of a real environment event or digest;
- safety or correctness of physical interventions;
- a complete causal-discovery capability;
- GameBench candidate performance or transfer;
- external benchmark reproduction or SOTA.

## Research direction

The differentiator is decision-sufficient causal discovery under stateful, costed, world-changing intervention: preserve unresolved equivalence classes when mechanisms cannot or need not be distinguished; spend intervention budget only when it can improve the terminal decision; and make each state transition auditable and replayable. See the companion protocol in `docs/research/SYMTHAEA_GAMEBENCH_TRANSITION_EVIDENCE_V0_1_2026-11-28.md`.
